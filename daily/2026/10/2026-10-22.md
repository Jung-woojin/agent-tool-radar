## 1. MCP Inspector 2.12.0

1. **정확한 이름** — MCP Inspector 2.12.0.
2. **공식 저장소/사이트** — [GitHub](https://github.com/modelcontextprotocol/inspector), [공식 문서](https://modelcontextprotocol.io/docs/2026-07-28/tools/inspector).
3. **유형** — MCP server 검사 도구. Web UI, CLI, TUI, experimental `mcpdo`를 한 패키지로 제공한다.
4. **정확히 하는 일** — MCP server에 연결해 tool/resource/prompt/auth 흐름을 탐색하고 호출·응답·오류를 검사한다.
5. **해결 문제** — MCP client에 붙이기 전에 schema, OAuth, transport, tool result, resource contract를 작은 환경에서 재현하기 어려운 문제.
6. **지원 client** — 독립 Web/CLI/TUI이며 특정 host에 종속되지 않는다. 검사 대상은 stdio·HTTP MCP server다.
7. **설치 방식** — `npx @modelcontextprotocol/inspector@latest`; CLI는 `--cli`, TUI는 `--tui`.
8. **오픈소스 여부** — 예.
9. **라이선스** — 전환기 혼합 구조다. 새 code/spec 기여는 Apache-2.0, 동의가 끝나지 않은 기존 기여는 MIT, 일반 문서는 CC-BY-4.0이다.
10. **로컬/클라우드** — 기본적으로 로컬 Node/Web UI. 원격 MCP server와 OAuth endpoint에 연결하면 network를 사용한다.
11. **필요 account/API key** — Inspector 자체 account는 필요 없다. 검사 대상 server가 OAuth/API key를 요구하면 해당 credential이 필요하다.
12. **read 권한** — MCP server의 공개 tool/resource/prompt metadata와 호출 결과를 읽는다.
13. **write 권한** — Inspector 자체는 설정·OAuth secret state를 저장한다. 연결한 MCP tool이 write tool이면 실제 외부 변경도 실행할 수 있다.
14. **shell/browser/Git/filesystem/network 권한** — stdio server 실행에는 local process/shell이 관여할 수 있고 Web UI와 HTTP/OAuth에는 browser/network가 필요하다. Git 권한은 연결한 server에 달렸다.
15. **security/privacy 위험** — OAuth token, client secret, stdio `env:` 값을 관리한다. OS keychain이 없으면 `~/.mcp-inspector/secrets.json`에 저장되며 encryption key가 없으면 평문일 수 있다.
16. **최근 update 날짜** — 2026-10-21 UTC.
17. **최근 release/중요 commit** — 2.12.0은 v2.0.0~2.11.0에 영향을 준 세 취약점을 수정했다: OAuth URL opener의 비-http(s) 실행 차단, Host allow-list로 DNS rebinding 차단, `/api/fetch` upstream body 4 MiB 제한. TLS, 429 `Retry-After`, OAuth verifier·credential 격리, `--load`도 추가·수정됐다.
18. **개발 활동성** — 높음. v2 개발 branch, milestone release, security advisory와 CI 변경이 함께 운영된다.
19. **issue/PR 상태** — 조사 시 GitHub repository API의 combined open issue/PR count는 26이었다. 이번 실행에서 개별 항목을 모두 판정하지 않았다.
20. **문서 품질** — 매우 높음. secret storage, TLS, migration, smoke test, App review, environment variable이 별도 문서로 분리돼 있다.
21. **코드 품질/테스트 상태** — 공식 문서는 format/lint/typecheck/build/unit, per-file 90% coverage gate, smoke와 Storybook, CodeQL을 명시한다. 이번 조사에서 test suite를 실행하지 않았다.
22. **무료/유료** — 무료 오픈소스. 연결하는 외부 service 비용은 별도다.
23. **실사용 장점** — MCP server를 실제 agent에 연결하기 전에 OAuth·Host·schema·oversize response 실패를 재현하고 CI화할 수 있다.
24. **실사용 단점** — 검사기 자체가 secret과 강한 tool을 만지므로 “개발 도구라 안전하다”는 가정이 위험하다. Web/TUI/CLI/mcpdo의 surface도 작지 않다.
25. **CV/AI 연구 workflow 적합성** — **매우 높음.** dataset browser, experiment registry, paper/RAG MCP를 연결하기 전에 read/write contract와 secret 저장을 검증하기 좋다.

**사실 / 저자 주장 / 추론:** 2.12.0의 세 취약점과 수정 범위는 공식 release 사실이다. “AI software factory” 등 생산성 표현은 프로젝트의 설명이다. CV 연구용 MCP 도입 전 gate로 사용할 가치가 높다는 평가는 본 보고서의 추론이다.

**진단 → 가설 → 최소 실험:** 연구용 MCP를 host에 바로 연결하면 OAuth URL, Host, 응답 크기, write tool의 위험을 뒤늦게 발견한다 → 2.12.0 Inspector로 세 보안 경계와 tool annotation을 먼저 검사하면 위험한 server를 production host 전에 걸러낼 수 있다 → local dummy server에서 custom-scheme OAuth URL, 허용되지 않은 Host, 5 MiB 응답을 각각 한 번 요청한다. **GO:** 3/3 차단, secret file 평문 0, read-only tool의 외부 write 0. **KILL:** URL opener 실행, bad Host 200, oversized body relay, secret 평문 저장.

## 오늘은 굳이 설치하지 않아도 되는 것

- **Gemini CLI 신규 설치:** 0.65.0 자체는 의미 있는 안정화지만 공식 README가 무료 사용자의 대체 client와 최신 model 비최적화를 명시한다. 기존 사용자의 upgrade trial로 한정하는 편이 낫다.
- **Agent Orchestrator의 cloud/mobile/browser 기능:** local worktree·diff 가치부터 확인한 뒤 추가해야 한다. 처음부터 모든 surface를 켜면 원인과 권한 경계가 섞인다.
- **Microsoft Agent Framework for Go 0.2.0:** embedding·vector store 설계는 좋지만 pre-release이고 현재 Woojin의 Python/PyTorch 연구 흐름에 바로 필요한 runtime은 아니다.
- **LangGraph 신규 배포:** 10월 21일 namespace 관련 security advisory가 공개됐다. 영향 버전과 patched version을 확정하기 전에는 upgrade·배포 결정을 미룬다.
- **MCP reference servers 2.0.0 재시험:** 전날 이미 주요 후보로 다뤘고 오늘 별도 stable delta가 없다.
- **mcp-use 2.11.0 반복 설치:** 전날 Inspector/UI 회귀 조건까지 검토했으며 새 stable 변화가 없다.

## 전날 대비 생태계 변화

전날은 research artifact와 장기 context 복구가 중심이었다. 오늘은 그 위에서 발생하는 **권한 결정과 재시도 부작용을 관찰·차단하는 층**이 강화됐다. Open-Science나 Planning with Files가 “무엇을 보존할 것인가”를 다뤘다면, MCP Inspector·Claude Code·Docker Agent는 “어떤 외부 행동이 허용됐고, 한 번만 실행됐으며, 안전하게 복구됐는가”를 다룬다. 다음 관찰 포인트는 Inspector 2.12.0의 실제 security regression 결과, Claude safety event의 누락률, Docker shared RAG의 cross-agent 격리, Agent Orchestrator의 live harness update가 running session 재현성에 미치는 영향이다.
