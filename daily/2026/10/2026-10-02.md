## 오늘 바로 시험할 Top 3

### 1. Graphify
**Type:** codebase knowledge graph + MCP + agent skill  
**Official repo:** https://github.com/Graphify-Labs/graphify  
**Why now:** Sep 30 activity included the official Cursor plugin and continued v8-era updates.

Graphify parses code deterministically with AST/tree-sitter, builds a knowledge graph, and exposes tools such as `query_graph`, `get_node`, `get_neighbors`, `shortest_path`, PR impact, and triage through MCP. It supports Claude Code, Cursor, Codex, Gemini CLI and can run locally over stdio or as a shared Streamable HTTP MCP server.

**Strong point for our workflow**
- Better than raw grep for architecture/call-graph questions.
- Useful for large research repos where an agent repeatedly has to rediscover data loaders, model registration, config inheritance, and evaluation flow.
- Local AST extraction means code itself does not need to leave the machine for the graph build.

**Security / privacy**
- Local stdio is the safest default.
- If serving over HTTP, keep loopback binding by default. If exposing `0.0.0.0`, use an API key and network controls.
- A committed graph can itself reveal architecture and symbol names, so do not casually publish internal-company graphs.

**License:** Apache-2.0  
**Verdict:** **Install / test now.**

Quick test:
1. Run Graphify on one medium research repo.
2. Ask “what connects dataset loading to the evaluation loop?”
3. Compare token use and answer quality against plain grep/search.

### 2. Scientific Agent Skills
**Type:** Agent Skills / plugin library for scientific research  
**Official repo:** https://github.com/K-Dense-AI/scientific-agent-skills  
**Latest release in catch-up window:** v2.70.0, Sep 29; repo was still active Oct 1.

The project has expanded from Claude-only scientific skills into a broader open Agent Skills / Agent Plugins package compatible with Claude Code, Cursor, Codex, Pi, Antigravity and other hosts implementing the standard. It contains a large library of research/data/database/scientific-computing skills.

**Why useful for us**
- Research workflow templates are more relevant than generic coding plugins.
- Could be mined for reproducible literature/database/data-analysis skill design.
- Useful reference if we later build custom CV-research skills for benchmark auditing, ablation planning, or experiment logging.

**Important license caveat**
The repository is MIT, but individual skills may carry different licenses. Do not assume every bundled skill is MIT merely because the root repo is.

**Security**
Many database/API skills require internet access and possibly API keys. Review individual `SKILL.md` files before enabling broad credentials.

**Verdict:** **Install selectively; do not blindly enable everything.**

Quick test:
- Pick one generic scientific writing/data-analysis skill.
- Use it on a non-sensitive public CV paper or benchmark table.
- Compare structure and reproducibility against our normal prompting workflow.

### 3. Compound Engineering
**Type:** multi-host engineering plugin / skill suite  
**Official repo:** https://github.com/EveryInc/compound-engineering-plugin  
**Catch-up activity:** v3.29.0 around Sep 24/25, v3.30.0 and v3.30.1 on Sep 29.

It packages an opinionated engineering loop around brainstorm → plan → build → review → capture learnings. The current project advertises support across many agent hosts including Claude Code, Cursor and Codex.

Recent 3.30.x changes focused less on flashy new commands and more on making skills respect requested scope, avoid unnecessary implementation, improve review judgment, and keep cross-model workers from stalling on large logs.

**Why this is interesting**
It attacks the same practical failure mode as Ponytail, but from a fuller workflow angle: not merely “write less code,” but preserve context and lessons across planning/review/implementation.

**Trade-off**
It is highly opinionated. That is useful if its workflow matches you, annoying if you prefer the agent to stay lightweight and ad hoc.

**License:** MIT  
**Verdict:** **Worth a controlled trial on one side project.**

Quick test:
- Run the same small feature through normal Codex/Claude vs Compound Engineering.
- Compare changed LOC, unnecessary abstractions, review findings, and total interaction cost.

## 4. Tencent BrowserSkill
**Type:** browser-use skill + CLI + extension  
**Official repo:** https://github.com/Tencent/BrowserSkill  
**Release:** v0.3.2 on 2026-09-30.

Recent releases added task-scoped website debugging, request/body capture, console/page context, request replay, performance metrics, browser profile selection, remote-browser support, full-page screenshots, and richer element interaction.

The attraction is obvious: it can let shell-capable agents use a real logged-in browser rather than a blank automation profile.

**Why useful**
- Testing internal dashboards or web UIs with real login state.
- Reproducing frontend issues while letting the agent collect network/console evidence.
- Potentially useful for automating repetitive web-based research workflows.

**Security caution: HIGH**
A real logged-in browser contains cookies, sessions, private pages and potentially company data. There have also been active security/connection issues discussed in the repo around the local WebSocket/extension boundary.

**Recommendation**
Use only with:
- a separate browser profile,
- minimal accounts logged in,
- no sensitive company sessions,
- local-only daemon unless remote access is intentionally configured.

**License:** MIT  
**Verdict:** **Powerful, but sandbox it.**

## 5. Microsoft Playwright MCP
**Type:** browser automation MCP  
**Official repo:** https://github.com/microsoft/playwright-mcp  
**Current package observed:** `@playwright/mcp` 0.0.83  
**License:** Apache-2.0

This remains one of the cleanest general-purpose browser MCP options: Playwright-backed automation exposed as MCP rather than a proprietary browsing abstraction.

**Why useful**
- UI regression checks
- test-case generation
- agent-controlled scraping/verification where normal HTTP fetch is insufficient
- reproducible browser actions in local development

**When I would choose it over BrowserSkill**
Use Playwright MCP when you want a controlled automation browser and reproducibility. Use BrowserSkill only when access to your existing logged-in browser state is truly necessary.

**Verdict:** **Baseline browser MCP to keep installed.**

## 6. Anthropic Claude Code Official Plugin Directory
**Type:** official plugin marketplace/index  
**Repo:** https://github.com/anthropics/claude-plugins-official

This is not one plugin; it is a curated official directory with Anthropic-maintained and third-party plugins.

**Why it matters**
The directory itself is useful as a discovery source for the daily radar because it reflects what the Claude Code plugin ecosystem is actually exposing to users.

**Security note**
Anthropic explicitly warns that inclusion does not mean it controls or fully verifies third-party MCP servers or bundled software. A plugin install can bring in code, hooks, MCP servers or external dependencies.

**Verdict:** **Use as a discovery index, not as a trust seal.**

## 7. codebase-memory-mcp
**Type:** codebase graph/index MCP  
**Repo:** https://github.com/DeusData/codebase-memory-mcp

Not a fresh release in this exact window, but maintainers were actively addressing Windows/index freshness and integration issues in late September.

Interesting capabilities include code indexing, graph search, outlines, graph comparison and project-level code memory.

**Why it stays on the watchlist**
It competes in the same problem space as Graphify but takes a different architecture and has a very active issue/PR stream.

**Current caution**
There have been open/active discussions around index freshness, nested repositories, Windows behavior, and agents sometimes preferring shell/grep instead of invoking the MCP tools.

**Verdict:** **Watch / compare against Graphify before standardizing.**

**Repo:** https://github.com/openai/role-specific-plugins

Do **not** treat this as a current install target. The public repository was archived on Sep 16, 2026 and is read-only. It is still useful as a reference for plugin structure, skills, connector bindings, and manifests, but not as an actively maintained plugin source.
