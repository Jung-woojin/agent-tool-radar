## 1. AIPOCH Open-Science 1.0.1

1. **정확한 이름** — AIPOCH Open-Science v1.0.1.
2. **공식 저장소/사이트** — [GitHub](https://github.com/aipoch/open-science), [공식 사이트](https://aipoch.com/open-science/).
3. **유형** — local-first, model-agnostic AI 연구 workbench와 desktop/CLI runtime.
4. **정확히 하는 일** — 문헌 검색, Python/R 실행, scientific connector, 표·그림·보고서 생성과 traceable artifact를 한 project에 묶는다.
5. **해결 문제** — 대화·노트북·파일 버전·출처가 흩어져 연구 결과를 다시 검증하기 어려운 문제.
6. **지원 client** — Windows, macOS, Linux desktop과 macOS/Linux standalone CLI.
7. **설치 방식** — 공식 installer; macOS는 `brew install --cask open-science`, standalone CLI는 `brew install aipoch/tap/open-science`.
8. **오픈소스 여부** — 예.
9. **라이선스** — Apache-2.0.
10. **로컬/클라우드** — local-first. 선택 model provider, web search, scientific connector는 network를 사용한다.
11. **계정/API key** — 선택한 model provider의 endpoint/key가 필요하다. local provider 사용 가능 범위는 provider 설정에 달렸다.
12. **read 권한** — 사용자가 연 project 파일, PDF, Notebook, 연결한 scientific source와 web 결과.
13. **write 권한** — project 파일, Notebook, 표·그림·보고서, portable `.science` package.
14. **shell/browser/Git/filesystem/network 권한** — Python/R compute, filesystem, web/network와 MCP connector를 사용할 수 있다. Git 사용은 연결한 tool에 따라 달라진다.
15. **보안/개인정보 위험** — dataset·논문·API key가 model/MCP provider로 나갈 수 있다. v1.0.1은 저장된 MCP OAuth credential을 authorization server에 묶어 사용하도록 보강했다.
16. **최근 update 날짜** — 2026-10-20 UTC.
17. **최근 release/중요 commit** — v1.0.1은 browser에서 `.science` package import, Windows updater handoff, session wait-state 표시, MCP OAuth와 PDF·literature·session recovery 수정을 포함한다.
18. **개발 활동성** — 1.0.0 직후 1.0.1 patch가 나왔고 release와 main의 issue/PR 처리가 계속된다.
19. **issue/PR 상태** — PDF, session, connector와 platform edge case가 공개 issue/PR로 추적된다. 완성된 장기 안정판으로 보기는 이르다.
20. **문서 품질** — 높음. 설치, model provider, data/permission/trust, package export, CLI가 분리돼 있다.
21. **코드/테스트 상태** — repository에 Vitest·Playwright 설정과 security policy가 있다. 이번 조사에서 test suite를 재실행하지 않았다.
22. **무료/유료** — core는 무료 오픈소스. model API와 외부 data service 비용은 별도다.
23. **장점** — 대화와 코드만 저장하는 대신 file version·Notebook record·verification evidence까지 portable package로 묶는다.

25. **CV/AI 연구 workflow 적합성** — **매우 높음.** 논문 PDF, 실험 코드, 표·그림, 결론을 하나의 검토 가능한 bundle로 보존하는 데 직접적이다.

**사실 / 저자 주장 / 추론:** 10월 20일 v1.0.1 release와 Apache-2.0, local-first 구조는 공식 저장소에서 확인한 사실이다. “재현 가능한 연구”는 저자 표현이다. CV 실험 provenance 손실을 줄일 가능성은 이 보고서의 추론이다.

**진단 → 가설 → 최소 실험:** 현재 연구 기록이 Markdown·Notebook·figure 폴더에 흩어져 결과의 출처를 다시 찾는 시간이 든다 → 작은 실험 하나를 `.science` package로 export/import하면 artifact 연결 누락을 측정할 수 있다 → 공개 이미지 10장으로 간단한 metric 계산, figure 1개, 출처 2개를 만든 뒤 새 profile로 import한다. **GO:** source URL 2/2, code·output·figure 3/3 복원, secret 포함 0, import 후 재실행 결과 일치. **KILL:** API key가 package에 포함되거나 file version/Notebook record가 누락된다.

16. **최근 update 날짜** — 2026-10-20 UTC.
17. **최근 release/중요 commit** — v3.25.0은 Hermes conversation별 named plan 선택, restart 뒤 selector 유지, invalid/missing plan fail-closed를 추가했다.
18. **개발 활동성** — 10월 17~20일 사이 3.24.x와 3.25.0 release가 연속됐다.
19. **issue/PR 상태** — release가 gateway selection gap과 concurrency 요구를 공개 issue에서 추적해 반영했다. 소수의 open issue/PR이 남아 있다.

24. **단점** — 여러 project/conversation을 쓰면 selector·hook·attestation 운영 부담이 생기고 plan 자체가 틀리면 오류를 지속시킨다.

**진단 → 가설 → 최소 실험:** 긴 실험 구현에서 compaction 뒤 이미 확인한 failure를 다시 조사한다 → plan/file injection이 있으면 재탐색과 잘못된 완료 선언이 줄어든다 → 동일한 12-step toy pipeline을 plugin on/off로 한 번씩 수행하고 중간에 context reset을 넣는다. **GO:** reset 뒤 next step 복원 1회 성공, 중복 tool call 25% 이상 감소, incomplete phase에서 종료 0. **KILL:** 다른 project plan 혼입, secret 재주입, 완료 gate가 2회 이상 불필요하게 막는다.

## 3. Raven 0.2.5

4. **정확히 하는 일** — built-in·third-party agent를 ACP, CLI, OpenAI-compatible API로 연결하고 dependency DAG와 shared memory로 조정한다.
5. **해결 문제** — research·coding·review agent가 서로 다른 interface와 machine에서 실행돼 상태·승인·실패를 한곳에서 추적하기 어려운 문제.
6. **지원 client** — WebUI/TUI와 ACP·CLI·OpenAI-compatible agent; 공식 README는 여러 third-party preset을 설명한다.
7. **설치 방식** — 공식 shell/PowerShell installer, Docker Compose, source checkout.
8. **오픈소스 여부** — 예.
9. **라이선스** — Apache-2.0.
10. **로컬/클라우드** — local host가 기본이며 등록된 remote machine과 optional EverOS Cloud memory를 사용할 수 있다.
11. **계정/API key** — 선택 model/provider와 remote/cloud integration에 credential이 필요하다. local-only 구성은 연결 범위에 따라 달라진다.
12. **read 권한** — workspace, session, memory, 연결 agent와 tool이 허용한 files/service.
13. **write 권한** — workspace files, memory, workflow state와 연결 agent가 수행하는 외부 action.
14. **shell/browser/Git/filesystem/network 권한** — agent에 따라 shell·browser·Git·filesystem·network와 remote execution까지 사용할 수 있다.
15. **보안/개인정보 위험** — remote delegation과 shared memory가 secret·private code 전파 범위를 넓힌다. 공식 README는 pre-alpha라고 명시한다.
16. **최근 update 날짜** — 2026-10-20 UTC.
17. **최근 release/중요 commit** — v0.2.5는 registered machine remote delegation, conditional DAG branch, native Windows install/start/cleanup, reserved device-name 거부를 추가·보강했다.
18. **개발 활동성** — release repository에 많은 commit과 issue/PR 활동이 이어지고 0.2.x patch cadence가 빠르다.
19. **issue/PR 상태** — Windows agent lifecycle, remote tool, multi-process cleanup 관련 issue가 release에 반영됐고 추가 open issue/PR이 남아 있다.
20. **문서 품질** — 중상. quick start, Docker, third-party agent, core system은 상세하지만 pre-alpha surface가 빠르게 변한다.
21. **코드/테스트 상태** — repository에 tests와 signed release artifact가 있다. 이번 조사에서 test suite나 remote acceptance를 재실행하지 않았다.
22. **무료/유료** — core는 무료 오픈소스. model API, optional cloud/remote infrastructure 비용은 별도다.
23. **장점** — 서로 다른 agent와 machine을 한 workflow로 묶고 trajectory·session을 관찰할 수 있다.
24. **단점** — 권한 surface가 넓고 pre-alpha이며, 단일 workstation 실험에는 도입 비용이 크다.
25. **CV/AI 연구 workflow 적합성** — **중상.** literature agent, experiment agent, reviewer를 나누는 데 유용하지만 private dataset을 연결하기 전 격리 trial이 필수다.

**사실 / 저자 주장 / 추론:** v0.2.5와 Windows/remote/DAG 변화는 공식 release 사실이다. “self-evolving” 성능과 benchmark 해석은 저자 주장이다. CV 연구 team orchestration의 실제 효율은 검증 전 추론이다.

**진단 → 가설 → 최소 실험:** multi-agent 실패가 model 답변보다 handoff·timeout·remote cleanup에서 발생한다 → 한 local agent와 한 disposable remote agent로 DAG를 제한하면 lifecycle 신뢰성을 측정할 수 있다 → 공개 toy repo에서 read-only repository map과 test-plan 작성 두 node를 조건부 branch로 실행한다. **GO:** task 2/2 완료, timeout 후 orphan process 0, repository write 0, trajectory로 실패 원인 1회에 재현. **KILL:** remote credential 전파, unexpected shell write, cancellation 뒤 process 잔존.

16. **최근 update 날짜** — stable 2026-10-19, canary 2026-10-20 UTC.
17. **최근 release/중요 commit** — stable 2.11.0이 10월 19일 공개됐다. 10월 20일 canary는 closed tab/back navigation 뒤 style hydration 수정을 넣었다가 다음 canary에서 되돌렸다.

19. **issue/PR 상태** — open issue/PR이 활발하며 v1→v2 migration과 App/Inspector edge case가 계속 다뤄진다.

22. **무료/유료** — framework는 무료 오픈소스. hosted deployment와 외부 service 비용은 별도다.
23. **장점** — tool schema와 View props를 연결하고 local Inspector에서 call·input·render를 함께 검증할 수 있다.
24. **단점** — MCP App client별 지원 차이와 UI hydration/OAuth/routing edge case가 남고 framework abstraction이 작지 않다.
25. **CV/AI 연구 workflow 적합성** — **중상.** dataset browser, benchmark card, experiment lookup tool을 interactive MCP App으로 만들 때 유용하다.

**사실 / 저자 주장 / 추론:** 2.11.0과 canary fix/revert는 공식 release 사실이다. “빠른 개발”은 저자 주장이다. CV benchmark inspector 제작 시간을 줄일지는 추론이다.

**진단 → 가설 → 최소 실험:** 연구용 MCP tool은 JSON output은 맞아도 schema, annotation, View state가 client별로 깨질 수 있다 → typed schema+Inspector로 read-only tool 하나를 먼저 만들면 contract·render 회귀를 작게 측정할 수 있다 → local CSV 20행을 읽어 metric table만 반환하는 App을 만든다. **GO:** invalid input 3/3 거부, structuredContent와 text 값 일치, reload/back 10회 style·hydration 실패 0, filesystem write 0. **KILL:** canary에서만 동작, client별 값 불일치, routing header가 외부 host로 전달된다.
