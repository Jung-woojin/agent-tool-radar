## 보안상 주의해서 써야 하는 것

- **agentmemory:** local-only, 별도 data dir, loopback bind로 시작한다. remote Redis는 TLS 제한과 instance 간 pub/sub 혼입 위험을 해결하기 전 사용하지 않는다.
- **Hive:** shell·browser·MCP를 한 번에 켜지 않는다. turn context 시험은 read-only fixture와 단일 queen으로 제한한다.
- **OpenResearch:** SSH·Slurm·Kubernetes credential을 첫 trial에 연결하지 않는다.
- **Feynman:** telemetry를 먼저 끄고 오류 메시지에 프로젝트 경로가 포함되지 않는지 확인한다.
- **Agentero:** 외부 MCP client, S3 sync, 번역 API를 첫 trial에서 모두 끈다.
- **Docker Agent:** Docker socket을 agent container에 넘기지 않고 source mount를 read-only로 둔다.
- **SoL-Pi:** remote reducer를 끄고 retained archive에 secret canary가 들어가지 않는지 검사한다.

## 오늘은 굳이 설치하지 않아도 되는 것

- **Hive:** turn context만 확인하려고 전체 multi-agent workspace를 주력 환경에 넣을 필요는 없다. Docker/VM 격리 시험 후 판단한다.
- **agentmemory:** 최근 scale·migration 이슈가 커서 모든 radar repo에 한 번에 연결할 단계가 아니다.
- **SoL-Pi:** Pi를 주 runtime으로 쓰지 않는다면 현재 효용이 제한적이다.
- **Fabric Agent Adapter:** Fabric host·contract를 채택할 계획이 정해지기 전에는 conformance surface가 과하다.
- **AgentWatch·moching·ARIS:** 이번 관찰 창의 변경이 기능보다 문서 중심이라 재평가 신호가 부족하다.

## 운영 결론

**[확인된 사실]** 오늘의 신호는 “더 많은 agent”보다 연구 근거의 계보, per-turn 최소 문맥, context 압축, 장기 기억의 경계, containerized 실행을 강화하는 쪽에 모였다. **[해석]** Woojin의 현재 병목은 도구 부족보다 문헌 주장→실험 run→artifact의 연결과 장기 자동화에서의 상태 drift다. **[전망]** Feynman·Agentero·OpenResearch를 각각 한 번의 격리 trial로 비교하면, 다음 주에는 세 도구를 모두 도입하는 대신 “문헌 audit”, “사람 중심 독서”, “실험 lineage” 중 실제로 줄어든 작업 시간을 기준으로 하나만 채택할 수 있다.
