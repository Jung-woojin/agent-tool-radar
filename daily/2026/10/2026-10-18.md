# AI Tool Radar — 2026-10-18

- 최근 24~72시간의 공개 저장소 12개를 검토했고, 공식 README·커밋·릴리스·열린 Issue를 교차 확인해 5개를 선정했다.
- 오늘의 핵심은 새 모델보다 **skill 공급망 검증, 사용자별 권한 격리, 다중 에이전트 관제, 감사 가능한 실행 기록**이다.

- 아래 평가는 **확인된 사실**, **저자 주장**, **해석**을 구분하며, 실행하지 않은 성능·보안 효과를 확정하지 않는다.

## 1. dsh-skills-anywhere

1. **정확한 이름** — `noteflowai/dsh-skills-anywhere`.
2. **공식 저장소/사이트** — [GitHub](https://github.com/noteflowai/dsh-skills-anywhere), [Hugging Face Space](https://huggingface.co/spaces/glayguo/dsh-skills-anywhere).
3. **유형** — Agent Skill 검색·검사·동기화 CLI 및 MCP 서버.
4. **무엇을 하는가** — **[저자 주장]** Claude Code, Codex, Gemini CLI, Cursor 등 여러 에이전트의 skill 디렉터리와 Git source를 찾아 `find_skills`, `open_skill`, `skill://` resource로 노출한다.
5. **해결 문제** — 에이전트마다 흩어진 `SKILL.md`의 중복, 누락 자원, 출처 불명, 버전 drift를 줄인다.
6. **클라이언트** — MCP를 지원하는 에이전트, DeepSeek Harness, CI 및 브라우저 기반 검사 흐름.
7. **설치** — `npx dsh-skills-anywhere add ...`; MCP는 `dsh-skills-anywhere mcp`. 시험은 `npx -y dsh-skills-anywhere@0.19.0 check <skill> --fail-on-repair`.
8. **오픈소스 여부** — 공개 저장소.
9. **라이선스** — MIT.
10. **로컬/클라우드** — 로컬 실행 중심이며 원격 Git source 동기화 때 네트워크를 쓴다.
11. **계정/API key** — 공개 Git source에는 필수 계정이 확인되지 않았다. 비공개 source 인증 방식은 별도 검증이 필요하다.
12. **읽기 권한** — 프로젝트·사용자 skill 디렉터리, 설정된 Git source, 캐시와 lock 정보.
13. **쓰기 권한** — `~/.dsh/skills-anywhere/cache`, 설정·lock 파일을 갱신한다.
14. **shell/browser/Git/filesystem/network** — filesystem과 Git/network를 사용한다. catalog/open 자체가 skill 내용을 자동 실행하는 기능은 아니다.
15. **보안·개인정보** — 원격 skill은 prompt 공급망이다. `--fail-on-hidden-characters`, `--fail-on-repair`, pinned ref/commit, content hash를 함께 써야 한다.
16. **최신 업데이트 날짜** — 최근 신호는 2026-10-17에 갱신된 DSH 0.2.x 호환 Issue #85다. 기본 브랜치 최신 커밋은 2026-10-10이다.
17. **최신 릴리스/커밋** — v0.19.0(2026-10-10), commit `c16fc16`; pinned skill 디렉터리에 로컬 변경이 있으면 예상 source commit load를 거부한다.
18. **활동성** — 저장소 생성 한 달 남짓, 6 stars·0 forks로 작지만 보안 관련 변경과 dependency PR이 이어진다.
19. **Issue/PR 상태** — 열린 항목 5개. DSH 0.2.x migration Issue와 MCP dependency 업데이트 PR이 열려 있다.
20. **문서 품질** — 설치, MCP 설정, cache/lock, 검사 플래그와 재현 가능한 예제가 구체적이다.
21. **코드/테스트 품질** — **[확인된 사실]** CI용 strict flag와 immutable commit 검증이 있다. **[해석]** 작은 사용자 기반 때문에 다양한 Windows 경로 조합은 직접 시험해야 한다.
22. **무료/유료** — 공개 MIT 소프트웨어. 별도 유료 플랜은 확인되지 않았다.
23. **장점** — 기존 skill 생태계를 교체하지 않고 검색·검증 계층만 추가할 수 있다.
24. **단점** — 또 하나의 source/cache 체계를 도입하며, 아직 생태계와 운영 이력이 작다.
25. **Woojin workflow 적합도** — **높음.** 여러 연구 자동화에서 재사용하는 skill을 commit pin과 strict check로 고정하면 자동화 drift를 줄일 수 있다.

**진단 → 가설 → 최소 실험:** 지금은 각 자동화가 로컬 지침을 직접 읽어 출처·버전 차이를 운영자가 추적한다 → skill catalog를 read-only로 붙이면 재사용성과 추적성이 좋아질 수 있다 → 복사한 비민감 skill 3개만 별도 폴더에 두고 `check --fail-on-repair --fail-on-hidden-characters`를 실행해 탐지율과 false positive를 기록한다.

## 2. blueclaw

1. **정확한 이름** — `yeomyeonggeori/blueclaw`.
2. **공식 저장소/사이트** — [GitHub](https://github.com/yeomyeonggeori/blueclaw), [문서](https://blueclaw.intern.kim/docs/quickstart).
3. **유형** — 다중 사용자용 POSIX 격리 agent host·daemon·CLI.
4. **무엇을 하는가** — **[저자 주장]** 요청자를 policy로 식별하고, 각 tool call을 그 사용자의 비권한 Linux 계정으로 실행하며, 부작용 호출은 승인 gate에 보류하고 event ledger에 남긴다.
5. **해결 문제** — 공유 에이전트가 서비스 계정 하나의 과도한 권한으로 모든 사용자의 작업을 수행하는 문제.
6. **클라이언트** — bluecollar, Claude Code, Codex, pi 같은 harness와 MCP 도구 catalog.
7. **설치** — 공식 quickstart에서 standalone runtime과 policy를 구성한 뒤 daemon을 시작한다. 단일 명령 설치는 README 첫 화면에 제시되지 않는다.
8. **오픈소스 여부** — 공개 저장소.
9. **라이선스** — Apache-2.0.
10. **로컬/클라우드** — self-hosted daemon; POSIX 사용자 격리를 전제로 한다.
11. **계정/API key** — 연결하는 모델·chat adapter의 credential이 필요할 수 있다. blueclaw 자체 공통 cloud 계정 요구는 확인되지 않았다.
12. **읽기 권한** — policy, identity, memory, scheduler, connector 입력과 사용자가 접근 가능한 파일.
13. **쓰기 권한** — 사용자의 OS 권한 범위에서 tool call 결과와 durable event ledger를 쓴다.
14. **shell/browser/Git/filesystem/network** — harness가 제공하는 tool에 따라 달라지며 daemon은 connector·HTTP·MCP를 다룬다.
15. **보안·개인정보** — 사용자별 POSIX UID 경계가 핵심이다. connector credential, ledger 보존 기간, 승인 응답 위조 방지 설정을 검토해야 한다.
16. **최신 업데이트 날짜** — 2026-10-17.
17. **최신 릴리스/커밋** — 공개 Release API에서 릴리스가 확인되지 않았다. 최신 commit `bdcbdc1`은 recall source를 embedding 의미로 순위화하는 변경이다.
18. **활동성** — 5 stars·0 forks지만 2026-10-17까지 빈번한 커밋이 이어지고 있다.
19. **Issue/PR 상태** — 열린 항목 15개. approval 결정 주체와 대화 routing 관련 설계 Issue가 남아 있다.
20. **문서 품질** — 개념, 구성요소, quickstart, 전체 reference가 연결되어 있다.
21. **코드/테스트 품질** — Go 기반이며 저장소에 approvals/security/policy 영역이 분리돼 있다. 보안 경계의 실제 강도는 배포 전 침투성 테스트가 필요하다.
22. **무료/유료** — 공개 Apache-2.0 소프트웨어. 호스팅 비용은 사용자 부담이다.
23. **장점** — 사람별 최소 권한과 승인 증거를 OS 사용자 경계에 연결한다.
24. **단점** — Windows 네이티브 자동화와 맞지 않고, 릴리스 자산보다 소스·문서 중심인 초기 상태다.
25. **Woojin workflow 적합도** — **중간.** Linux 연구 서버를 여러 사람이 공유할 때 가치가 높고, 현재 Windows 단독 운영에는 과하다.

**진단 → 가설 → 최소 실험:** 장기 실행 agent host가 하나의 강한 계정으로 작업하면 사용자별 책임 경계가 흐려진다 → Linux VM에서 서로 다른 UID로 실행하면 승인과 파일 접근이 분리될 수 있다 → 임시 VM의 두 테스트 계정으로 동일 파일 읽기와 타 사용자 경로 쓰기를 요청해 허용·거부·ledger 기록을 확인한다.

## 4. Agent Assembly

1. **정확한 이름** — `AI-agent-assembly/agent-assembly`.
2. **공식 저장소/사이트** — [GitHub](https://github.com/AI-agent-assembly/agent-assembly), [공식 사이트](https://agent-assembly.com).
3. **유형** — agent governance runtime, gateway, sidecar proxy, SDK hook, Linux eBPF 관측 계층.
4. **무엇을 하는가** — policy·budget·network egress 판단과 tamper-evident audit chain을 제공하고 `aasm integrations`로 Codex 등 dev tool의 설치 경계를 검증한다.
5. **해결 문제** — agent 호출이 정책·비용·egress 통제 밖에서 실행되고 사후 증거가 흩어지는 문제.
6. **클라이언트** — 자체 agent, Claude Code, Codex, Copilot, Windsurf integrations.
7. **설치** — CLI-only installer, Homebrew, GitHub release가 있다. review-first는 installer를 내려받아 읽은 뒤 실행하도록 문서화했다.
8. **오픈소스 여부** — 공개 저장소.
9. **라이선스** — Apache-2.0.
10. **로컬/클라우드** — 현재 로컬 runtime/gateway/proxy 중심. hosted SaaS control plane은 README에서 “coming soon”.
11. **계정/API key** — 로컬 CLI 자체 계정 요구는 확인되지 않았다. 통제 대상 모델·서비스 credential은 별도다.
12. **읽기 권한** — agent/tool request, policy, budget, network destination, audit state.
13. **쓰기 권한** — config·policy·state·logs와 hash-chained audit 기록.
14. **shell/browser/Git/filesystem/network** — dev tool launch path와 proxy network를 다룬다. eBPF 관측은 Linux 전용이다.
15. **보안·개인정보** — proxy CA trust와 트래픽 검사 범위를 명확히 해야 한다. SDK hook은 문서상 보안 경계가 아니며, eBPF syscall guard는 비동기라 최초 syscall 자체는 실행될 수 있다.
16. **최신 업데이트 날짜** — 2026-10-17.
17. **최신 릴리스/커밋** — v0.0.1-rc.7(2026-09-17, prerelease). 최신 commit `41e7842`는 URL의 실제 host로 network allowlist를 판단하도록 수정했다.
18. **활동성** — 2 stars·1 fork로 외부 채택 신호는 작지만, 수천 단위 PR/Issue 번호와 당일 보안 수정이 보인다.
19. **Issue/PR 상태** — 열린 항목 44개. IPv6 host parsing, PII anomaly event, Codex 경계 검증 PR이 진행 중이다.
20. **문서 품질** — 지원 행렬, known bypass, review-first 설치, 제거·데이터 보존 동작이 상세하다.
21. **코드/테스트 품질** — Rust workspace, nextest·cargo-deny, QA 항목이 문서화됐다. 아직 RC이므로 API·운영 안정성은 확정할 수 없다.
22. **무료/유료** — 로컬 오픈소스는 Apache-2.0. 예정 SaaS 가격은 확인되지 않았다.
23. **장점** — 정책 판단과 감사 검증을 한 계층에 모으고 `aasm audit verify-chain`으로 사후 검증한다.
24. **단점** — Windows host adapter가 지원되지 않으며, macOS proxy도 source build 조건이 있고 RC 단계다.
25. **Woojin workflow 적합도** — **중간.** Linux CI/연구 서버의 egress 감사에는 유용하지만 Windows 주 환경의 즉시 도입에는 맞지 않는다.

**진단 → 가설 → 최소 실험:** 현재 agent 실행 기록은 개별 도구 로그에 흩어진다 → Linux test VM에서 CLI-only policy/audit를 붙이면 요청별 승인·egress 증거를 일관되게 남길 수 있다 → runtime/proxy 없이 CLI-only로 sample policy를 적용하고 허용 1건·차단 1건 뒤 audit chain 검증 시간과 기록 필드를 확인한다.

## 5. Codewhale

1. **정확한 이름** — `Codewhale-hq/Codewhale`.
2. **공식 저장소/사이트** — [GitHub](https://github.com/Codewhale-hq/Codewhale), [공식 사이트](https://codewhale.net).
3. **유형** — 다중 모델 coding agent engine·TUI·headless CLI·local web/runtime API.
4. **무엇을 하는가** — 프로젝트 읽기, 파일 수정, command 실행, 검증을 수행하며 plan/work/operate mode, approval posture, undo/restore, receipt를 제공한다.
5. **해결 문제** — 모델·클라이언트마다 달라지는 도구 권한과 세션 증거를 하나의 local engine으로 통일한다.
6. **클라이언트** — terminal, headless CI, localhost web client, Runtime API, community VS Code extension.
7. **설치** — Windows는 `winget install HunterBown.CodeWhale`; npm·Cargo·release installer도 제공한다.
8. **오픈소스 여부** — 공개 저장소.
9. **라이선스** — MIT.
10. **로컬/클라우드** — local engine 중심. hosted model과 Ollama/vLLM/SGLang 같은 local model을 모두 지원한다.
11. **계정/API key** — 로컬 모델은 계정 없이 가능하다. hosted provider는 해당 key가 필요하며 Codewhale 계정 route는 선택 사항이다.
12. **읽기 권한** — 프로젝트 파일, Git 상태, 설정·session, 선택한 provider 요청 문맥.
13. **쓰기 권한** — work/operate mode에서 파일·Git 작업·command를 수행하고 session·receipt를 저장한다.
14. **shell/browser/Git/filesystem/network** — 네 영역 모두 가능하다. Computer Use plugin은 별도 검토·활성화가 필요하다.
15. **보안·개인정보** — `/preview-request`로 전송 payload를 볼 수 있다. telemetry usage count는 기본 활성이고 설정으로 끌 수 있다. OS sandbox는 macOS/Linux 지원 설명이 중심이다.
16. **최신 업데이트 날짜** — 2026-10-17.
17. **최신 릴리스/커밋** — v0.10.1(2026-10-08); 최신 commit `f53d9a4`는 main 직접 landing과 drift check를 맞춘 운영 문서 변경이다.
18. **활동성** — 41,096 stars·3,568 forks, 열린 항목 206개로 오늘 선정군 중 외부 채택 신호가 가장 크다.
19. **Issue/PR 상태** — Linux `bwrap` symlink mount 오류와 turn snapshot `git commit-tree` 오류 등 실제 운영 결함이 열려 있다.
20. **문서 품질** — 설치, provider, permission, sandbox, receipt, Runtime API, 한국어 README까지 폭넓다.
21. **코드/테스트 품질** — Rust 기반이며 CI badge, release checks, contract tests가 문서·변경 기록에 나타난다. 열린 회귀 Issue는 pin과 rollback 계획의 필요성을 보여준다.
22. **무료/유료** — core는 MIT. 사용 모델·호스팅 비용은 provider 선택에 따라 달라진다.
23. **장점** — 모델 선택, 승인, receipt, 복구, headless와 interactive 실행을 한 engine에 통합한다.
24. **단점** — 이미 Codex 중심으로 구성한 workflow와 기능 중복이 크고, 새 session·provider·telemetry 관리면이 생긴다.
25. **Woojin workflow 적합도** — **중상.** 대체 엔진 후보로는 강하지만 현재 자동화에 즉시 병합하기보다 동일 과제 비교가 적절하다.

**진단 → 가설 → 최소 실험:** 현재 Codex 자동화의 대체 가능성과 local model fallback 품질을 정량 비교하지 않았다 → 같은 작은 repository task를 두 엔진에 주면 권한 요청·변경 품질·증거 수준을 비교할 수 있다 → 샘플 repo에서 “실패 테스트 하나 수정”을 plan/ask posture로 실행해 총시간, 승인 횟수, diff 정확성, receipt 완결성을 기록한다.

## 오늘 바로 설치/시험할 Top 3

1. **dsh-skills-anywhere** — 설치보다 먼저 `npx -y ... check`의 read-only 검사만 수행한다. 성공 기준은 sample skill 3개 모두 source·resource 오류가 설명 가능하고 원본 파일 변화가 0인 것이다.
2. **Pane** — 로컬 전용으로 Codex session 2개만 띄운다. Remote Pane, workspace write, analytics는 비활성 상태를 확인한 뒤 시험한다. 성공 기준은 승인 대기 탐지 100%, orphan process 0, 추가 RAM 사용량 기록 완료다.
3. **Codewhale** — 기존 저장소가 아닌 disposable repo에서 plan/ask mode만 쓴다. 성공 기준은 동일 task의 diff가 테스트를 통과하고 모든 shell/file action이 receipt에 남는 것이다.

## CV/AI 연구·코딩 workflow에 특히 유용한 것

- **dsh-skills-anywhere:** 논문 요약, benchmark 감시, repo audit skill을 여러 agent에서 같은 commit으로 재사용할 때 가장 직접적이다.
- **Pane:** 학습 코드, 데이터 검사, 문헌 조사 세션을 동시에 돌릴 때 어느 세션이 승인·입력 대기인지 보여주는 관제층으로 유용하다.
- **Codewhale:** local VLM/Ollama와 hosted model을 같은 작업에 비교하거나, 연구 코드 변경의 승인·receipt를 보관하는 실험에 적합하다.
- **blueclaw/Agent Assembly:** 공동 연구 Linux 서버나 장기 실행 CI로 범위가 넓어질 때 권한·egress 감사 후보가 된다.

## 보안상 주의해서 써야 하는 것

- **Pane:** remote workspace와 terminal은 사실상 파일·shell 권한을 확장한다. telemetry Issue #1051이 해결·검증되기 전에는 민감 저장소와 Remote Pane을 연결하지 않는다.
- **Agent Assembly:** proxy CA를 신뢰시키면 관찰 범위가 커진다. RC를 운영 트래픽에 넣지 말고 격리 VM에서만 확인한다.
- **blueclaw:** durable ledger에 prompt, identity, tool 결과가 남을 수 있으므로 보존·삭제·접근 정책이 먼저다.
- **dsh-skills-anywhere:** remote skill을 실행 지침으로 소비하기 전에 commit pin, hidden-character 검사, 사람이 읽는 review가 필요하다.
- **Codewhale:** `--auto`나 Full Access를 초기 시험에 쓰지 않고 telemetry와 provider key 저장 위치를 확인한다.

## 오늘은 굳이 설치하지 않아도 되는 것

- **blueclaw:** 현재 Windows 단독 환경에는 POSIX 사용자 격리의 이점을 얻기 어렵다.
- **Agent Assembly:** v0.0.1 RC이고 Windows host adapter가 없어, Linux CI 보안 과제가 생길 때 다시 평가하는 편이 낫다.
- **MulmoTerminal·Rove·Garcon·Cezar:** 오늘은 Pane과 역할이 겹친다. Pane 실험이 실패한 원인을 분명히 한 뒤 대안을 고른다.
- **digital-employee:** package contract가 필요한 조직형 workflow가 아직 구체화되지 않았다.
- **mabrid·guhbot:** 활동은 신선하지만 외부 사용·Issue 신호가 적어 관찰을 우선한다.

## 운영 결론

**[확인된 사실]** 최근 신호는 agent 자체 능력보다 공급망 고정, 권한 경계, 관제, 감사 증거에 집중돼 있다. **[해석]** Woojin의 자동화는 이미 생성 능력이 충분하므로 오늘의 가장 작은 개선은 새 agent를 추가하는 것이 아니라 skill 입력을 검증하고 병렬 세션을 관측 가능하게 만드는 것이다. **[전망]** dsh strict check와 Pane 로컬 trial이 성공하면 다음 단계는 “모든 자동화에 설치”가 아니라 한 개 radar job에만 pin하여 1주 동안 실패율·승인 누락·운영 시간을 비교하는 것이다.
