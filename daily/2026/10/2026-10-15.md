- **Yomitomo**에는 보안 실험이 끝나기 전 미공개 논문·심사 문서·계약 자료를 넣지 않는다.

## 10~30분 안에 할 수 있는 테스트 시나리오

| 시간 | 대상 | 절차 | 측정값과 통과 기준 |
|---:|---|---|---|
| 20분 | Wingman | 공개 CV 주제 10개를 2-source/3-source로 질의 | citation-target ≥9/10, unsupported claim 0, p95 <30초, trace 누락 0 |
| 20분 | Yomitomo | 공개 PDF 2개 import, 질문 10개, backup, telemetry off 관찰 | 정확한 source jump ≥9/10, secret 검출 0, telemetry 요청 0 |
| 15분 | Orca | 제한 모드의 throwaway repo에서 10개 수정·검증 | verifier 10/10, argv prompt 0, workspace 밖 diff 0, duplicate 0 |
| 20분 | Agent Knock Knock | 가짜 대화 2개에 10회 send/reconnect | exact target 10/10, duplicate turn/callback 0, uncertain replay 0 |
| 30분 | Terminal Setup | VM snapshot, report, Codex-only update, rollback | 예상 밖 도구 0, unnamed agent 변경 0, rollback diff 0 |

## 최종 판단

오늘의 공통 신호는 기능 수보다 **경계가 관찰 가능한가**다. Wingman은 citation·trace, Yomitomo는 source jump·backup, Orca는 verifier·workspace, Agent Knock Knock은 target·receipt, Terminal Setup은 install scope를 각각 검증 단위로 제공한다. 이 다섯 도구 모두 제작자의 안전·성능 설명만으로 채택하지 않고 위 최소 실험의 GO 기준을 통과한 경우에만 연구 워크플로에 편입한다.
