## 1. Graphify 0.9.94

1. **이름:** Graphify 0.9.94.
2. **공식 저장소/사이트:** https://github.com/Graphify-Labs/graphify · https://www.graphify.com/
3. **유형:** 로컬 코드·문서 지식 그래프 CLI/Skill/MCP 연동 도구.
4. **무엇을 하는가:** tree-sitter로 코드 구조를 추출하고 문서·SQL·PDF·미디어를 같은 그래프로 연결한다.
5. **해결 문제:** 에이전트가 매 턴 넓은 텍스트 검색을 반복하거나 잘못된 호출 관계를 사실처럼 취급하는 문제.
6. **지원 클라이언트:** Claude Code, Cursor, Codex, Gemini CLI용 Skill; 별도 MCP 서버 경로.
7. **설치:** `uv tool install graphifyy` 후 `graphify install --project --platform codex`. 공식 패키지명은 `graphifyy`다.
8. **오픈소스:** 예.
9. **라이선스:** 저장소에 Apache-2.0과 MIT 라이선스가 함께 표시된다.
10. **로컬/클라우드:** 코드 AST는 로컬. 문서·미디어 semantic pass는 선택한 백엔드로 나갈 수 있다.
11. **계정/API 키:** 코드 전용은 불필요. OpenAI·Kimi 등 선택 백엔드는 해당 키가 필요하며 Ollama/`backend=none`은 로컬 경로다.
12. **읽기 범위:** 지정한 코드베이스, 문서, 설정, PDF·미디어와 Git 메타데이터.
13. **쓰기 범위:** 기본 출력 그래프, 캐시, 설치한 Skill 파일; 선택 시 Neo4j/FalkorDB로 push.
14. **권한:** 로컬 파일 읽기·쓰기와 CLI 실행. 선택 백엔드는 네트워크, MCP 연결은 해당 서버 권한을 추가한다.
15. **보안/개인정보:** 0.9.94는 주석·docstring에서 API 키·Bearer 토큰·개인키 헤더·자격증명 URL 모양을 rationale 라벨로 내보내기 전에 가린다. 그래도 원본 저장소에 비밀이 있으면 스캔 범위를 최소화해야 한다.
16. **최근 업데이트:** 0.9.94, 2026-10-22 16:19 UTC.
17. **릴리스 변화:** 긴 파일을 subagent가 일부만 읽으면 `.graphify_partial.txt`로 표시하고 다음 `--update`에서 다시 추출한다. 잘못된 bare method 링크, `ast_empty` 재큐잉, 다중 언어 타입·호출 해석도 수정했다.
18. **활동성:** 릴리스 노트가 15명 규모 기여와 다수 PR을 묶고 있으며 0.9.93 뒤 이틀 만에 후속 릴리스가 나왔다.
19. **이슈/PR 상태:** 0.9.94는 커뮤니티 PR 기반 수정이 중심이다. 범위가 넓어 AST 캐시 스키마 변경 시 최초 재추출 비용을 확인해야 한다.
20. **문서 품질:** 설치, 입력 종류, backend, CLI/MCP 차이, 보안 경계를 구체적으로 문서화했다.
21. **코드/테스트 품질:** 언어별 회귀 수정과 캐시 스키마 bump가 명시된다. 다만 실제 프로젝트 정확도는 별도 검증이 필요하다.
22. **무료/유료:** 핵심 오픈소스는 무료. 선택한 외부 모델·DB 운영비는 별도다.
23. **장점:** 관계마다 `EXTRACTED`/`INFERRED` 근거를 구분하고, 부분 추출을 조용히 성공 처리하지 않는다.
24. **단점:** 미디어·문서 semantic pass는 모델 편향과 외부 전송이 개입하며, 큰 저장소 최초 재인덱싱 비용이 있다.
25. **CV/AI workflow 적합성:** 모델 코드·데이터 파이프라인·논문 메모를 한 그래프로 묶어 “이 augmentation 설정이 어느 training/eval 경로에 영향을 주는가”를 추적하기 좋다.

**진단 → 가설 → 최소 실험:** 기존 코드 검색은 호출 관계와 문서 근거를 분리하지 못한다 → Graphify의 근거 태그와 부분 추출 복구가 잘못된 영향 분석을 줄일 것이다 → 작은 PyTorch 저장소에서 `backend=none`으로 graph를 만들고 의도적으로 긴 파일 추출을 중단한 뒤 `--update` 실행. **GO:** 재실행 후 누락 함수 0개, 비밀 샘플이 출력 라벨에 0회 노출, 수동 확인 20개 edge 중 18개 이상 타당. **KILL:** 비밀 노출 1회 또는 부분 파일이 재처리되지 않음.

## 2. CodeGraph-Rust 0.55.2

1. **이름:** CodeGraph-Rust 0.55.2.
2. **공식 저장소/사이트:** https://github.com/sunerpy/codegraph-rust · https://firlab.app/codegraph/
3. **유형:** Rust 단일 바이너리 코드 지식 그래프, CLI, MCP 서버, 로컬 뷰어.
4. **무엇을 하는가:** tree-sitter 추출 결과를 SQLite/FTS5에 저장하고 symbol, caller/callee, impact, path를 질의한다.
5. **해결 문제:** LLM이 매번 저장소 구조를 다시 읽어 토큰을 소모하고 서로 다른 답을 만드는 문제.
6. **지원 클라이언트:** MCP 클라이언트, 쉘 CLI, 로컬 브라우저 뷰어.
7. **설치:** GitHub Release의 체크섬 검증 설치기 또는 사전 빌드 archive; 소스는 `cargo install --locked --git ... codegraph-rs`.
8. **오픈소스:** 예.
9. **라이선스:** MIT.
10. **로컬/클라우드:** 인덱스·daemon·HTTP transport 모두 로컬이 기본이다.
11. **계정/API 키:** 핵심 기능에 불필요.
12. **읽기 범위:** 선택 프로젝트의 소스·설정·Git 상태.
13. **쓰기 범위:** 프로젝트 안 로컬 인덱스와 상태 파일.
14. **권한:** 파일시스템 읽기·프로젝트 한정 쓰기, 로컬 프로세스/포트. 기본 분석에 외부 네트워크가 필요 없다.
15. **보안/개인정보:** 저장소는 project-contained filesystem access와 fail-closed ambiguity를 계약으로 제시한다. 설치 스크립트 대신 archive·SHA256·attestation 검증이 더 안전하다.
16. **최근 업데이트:** 0.55.0(10-21), 0.55.1·0.55.2(10-22).
17. **릴리스 변화:** 0.55.0은 재인덱싱 필요 파일과 parse error를 표시하고 C/C++·CFML·CommonJS 추출을 확장했다. 0.55.1은 daemon 시작 전 구형 index upgrade, 0.55.2는 `uninit` tombstone 아래 상태 전이를 바로잡았다.
18. **활동성:** 하루 동안 기능 릴리스와 두 번의 상태 복구 패치가 이어졌다.
19. **이슈/PR 상태:** 공식 화면 기준 open issue 1, PR 1. 작은 프로젝트이므로 bus factor를 함께 본다.
20. **문서 품질:** 설치·체크섬·attestation·정적 분석 한계·benchmark 방법을 명시한다.
21. **코드/테스트 품질:** byte-stable golden fixture, clean index와 incremental 결과 동등성, `make check`/`make ci` 경로를 제공한다.
22. **무료/유료:** 무료 오픈소스.
23. **장점:** 모델 호출·embedding 없이 결정적이며 결과를 로컬에 유지한다.
24. **단점:** reflection·registry·event bus·생성 코드의 런타임 관계는 정적 그래프 밖일 수 있다.
25. **CV/AI workflow 적합성:** Python/C++/Rust가 섞인 CV inference·CUDA extension 저장소에서 호출 영향 범위를 빠르게 좁히는 데 유용하다.

**진단 → 가설 → 최소 실험:** 기존 인덱스가 삭제/구버전 상태에서 되살아나면 에이전트가 낡은 근거를 사용한다 → 0.55.2의 tombstone 수정이 상태 정합성을 지킬 것이다 → 200~500파일 repo에서 init→uninit→구버전/신버전 status→명시 init을 순서대로 실행. **GO:** uninit 뒤 query가 실패하고 명시 init 전 index가 0회 자동 복구되며, clean/sync 결과 SHA가 일치. **KILL:** 삭제한 index가 암묵적으로 복원되거나 parse error가 상태에서 사라짐.

## 4. Kinocut 1.16.2

## 판단

**확인된 사실:** 위 버전과 변화는 각 프로젝트의 공식 GitHub 릴리스·README에서 확인했다. Graphify와 CodeGraph-Rust는 로컬 코드 그래프의 실패 감지를 강화했고, Kinocut은 영상 입력 경계를 명시적으로 검증한다.

**저자 주장:** 각 프로젝트의 성능·도구 수·지원 범위는 저장소 저자의 설명이다. 이 보고서는 설치나 자체 benchmark로 그 수치를 독립 재현하지 않았다.

**해석:** 오늘의 가장 값싼 이득은 새 에이전트를 늘리는 것이 아니라, 기존 연구 repo에서 구조 근거와 영상 산출물의 재현성을 측정하는 것이다. 따라서 Top 3를 로컬·공개 fixture에서 먼저 시험하고, Agent Swarm과 Codex++는 격리 실험의 GO 조건을 통과한 뒤에만 실데이터로 넓힌다.
