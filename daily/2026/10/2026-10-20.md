## 1. Model Context Protocol servers v2.0.0

1. **정확한 이름** — Model Context Protocol reference servers v2.0.0.
2. **공식 저장소/사이트** — [GitHub](https://github.com/modelcontextprotocol/servers), [MCP Registry](https://registry.modelcontextprotocol.io/).
3. **유형** — MCP reference server 모음.
4. **정확히 하는 일** — Everything, Filesystem, Memory, Sequential Thinking, Fetch, Git, Time의 reference implementation을 제공한다.
5. **해결 문제** — MCP client·server가 같은 protocol era와 SDK 동작을 구현하는지 확인할 공통 기준이 부족한 문제.
6. **지원 client** — 표준 MCP client. README는 Claude Desktop 예시를 제공하며 다른 client는 MCP 호환 범위에서 사용할 수 있다.
7. **설치 방식** — TypeScript server는 `npx`, Python server는 `uvx` 또는 `pip`; v2 npm package는 Node.js 24 이상을 요구한다.
8. **오픈소스 여부** — 예.
9. **라이선스** — 신규 기여는 Apache-2.0, 기존 코드는 MIT가 함께 존재한다.
10. **로컬/클라우드** — 기본 server process는 로컬. Fetch와 외부 resource를 쓰는 server는 network를 사용한다.
11. **계정/API key** — reference server 자체에는 공통 계정이 없다. 외부 서비스 server를 붙일 때는 해당 credential이 필요하다.
12. **read 권한** — Filesystem의 허용 directory, Git repository, Memory store, URL response 등 server별로 다르다.
13. **write 권한** — Filesystem·Git·Memory server는 설정과 tool에 따라 파일, index, knowledge graph를 쓸 수 있다.
14. **shell/browser/Git/filesystem/network 권한** — Git·filesystem·network가 server별로 직접 노출된다. 브라우저 로그인 session은 reference set의 기본 요구가 아니다.
15. **보안/개인정보 위험** — 공식 README 자체가 production-ready가 아닌 reference implementation이라고 경고한다. allowed directory와 client approval 없이 production repo에 연결하면 안 된다.
16. **최근 update 날짜** — 2026-10-19 UTC.
17. **최근 release/중요 commit** — [v2.0.0](https://github.com/modelcontextprotocol/servers/releases/tag/v2.0.0)은 TypeScript/Python SDK v2, 2026-07-28 era 지원, npm provenance를 포함한다. Python Fetch/Git/Time은 `mcp>=2.3,<3`이다.
18. **개발 활동성** — 같은 날 release audit, CI supersede 처리, Python server 직렬화·validation 보정이 연속 병합됐다.
19. **issue/PR 상태** — 공개 이슈에는 Memory tool의 idempotent hint, tool schema 정합성 같은 protocol-level 항목이 남아 있다.
20. **문서 품질** — 높음. reference/production 경계, Windows `npx` wrapper, release·security 문서를 명시한다.
21. **코드/테스트 상태** — release issue 기록상 7개 build와 7개 publish job이 성공했다. 이 보고서에서는 재실행하지 않았다.
22. **무료/유료** — 무료 오픈소스. 외부 API나 model 비용은 별도다.
23. **장점** — MCP v2 migration을 vendor-neutral fixture로 검증할 수 있고 package provenance가 있다.
24. **단점** — reference server를 그대로 production tool로 오해하기 쉽고, v1→v2·Node 24 전환 비용이 있다.
25. **CV/AI 연구 workflow 적합성** — **높음.** 연구 repository용 custom MCP를 만들 때 filesystem/Git/Memory의 schema·error·approval 회귀 기준으로 유용하다.

**진단 → 가설 → 최소 실험:** 기존 MCP client가 protocol era 변경 뒤에도 tool 목록은 보이지만 error code·pagination·write boundary가 달라질 수 있다 → v2 reference server로 contract test를 만들면 client-specific 회귀를 20분 안에 드러낼 수 있다 → 빈 임시 directory에서 Filesystem·Git·Memory 각각 5개 read와 2개 거부되어야 할 write를 실행한다. **GO:** 예상 tool 100% 발견, 허용 read 15/15 성공, 경계 밖 write 2/2 거부, malformed call이 protocol error로 반환. **KILL:** 작업 directory 밖 쓰기 1건, client가 tool을 누락하거나 unknown call을 성공 처리.

18. **개발 활동성** — 10월 19일에도 live model catalogue 검사, warn-mode safe-output policy, staged skill 등록 보정이 main에 병합됐다.

22. **무료/유료** — extension은 오픈소스. Actions minute와 선택 engine 사용료는 별도다.
23. **장점** — agent의 reasoning과 실제 GitHub write를 job boundary로 분리하고 permission을 review 가능한 YAML로 남긴다.
24. **단점** — compiler·runner·engine·MCP gateway·safe output이 겹쳐 debugging surface가 크고, Actions/engine 비용이 누적될 수 있다.
25. **CV/AI 연구 workflow 적합성** — **높음.** benchmark regression triage와 실패 log 분류에는 좋지만, 현재 radar의 단순 Markdown 저장은 직접 file API가 더 작고 명확하다.

**진단 → 가설 → 최소 실험:** 자동 연구 repo에서 agent가 조사와 write를 한 job에서 처리하면 권한과 실패 원인을 분리하기 어렵다 → read-only compile+safe-output만 허용하면 결과 품질을 유지하면서 write surface를 줄일 수 있다 → fork가 아닌 throwaway private repo에서 issue/PR 생성 없이 `audit`와 compile만 실행한다. **GO:** agent job `contents: read`, write permission 0, redacted secret 0 노출, 실패 원인 1회에 식별, outbound domain 목록 완전. **KILL:** compile 결과에 예상 밖 `contents: write`, token/log 노출, 자동 issue 생성.

12. **read 권한** — scene graph, assets, application state, screenshots, logs, adapter metadata.
13. **write 권한** — scene·node graph·materials·render queue·files와 UI action을 adapter 범위에서 변경할 수 있다.

15. **보안/개인정보 위험** — 실제 desktop app과 UI를 조작하므로 잘못된 instance routing, stale observation, remote listener 노출, asset overwrite가 주요 위험이다.
16. **최근 update 날짜** — 2026-10-19 UTC.
17. **최근 release/중요 commit** — [v0.20.46](https://github.com/dcc-mcp/dcc-mcp-core/releases/tag/v0.20.46)은 reviewed adapter RC pilot, admin workspace 재설계, quoted stdio arg 보존, interrupted updater 복구를 포함한다.
18. **개발 활동성** — release 직후 schema digest pin과 off-PATH CUA probe, bounded keypress evidence 보정이 이어졌다.
19. **issue/PR 상태** — tool response mis-correlation, remote listener policy, UIA timeout recovery 같은 고위험 edge case가 공개 추적 중이다.
20. **문서 품질** — 높음. adapter coverage, contracts, CLI, gateway, REST, recovery/undo를 구체적으로 문서화한다.
21. **코드/테스트 상태** — schema immutability gate, user-install discovery regression test, CI badge와 signed release artifact가 있다. release 직후 pin 누락이 main을 붉게 만든 사실도 commit에 남아 있다.
22. **무료/유료** — core는 무료 오픈소스. DCC 제품 라이선스와 cloud/asset service 비용은 별도다.
23. **장점** — write 후 read-back postcondition과 bounded discovery로 CV/DCC automation을 검증 가능한 call로 바꾼다.
24. **단점** — ecosystem과 권한 surface가 매우 크고, host별 상태·main-thread·UI fallback 때문에 작은 research script보다 운영 부담이 크다.
25. **CV/AI 연구 workflow 적합성** — **중상.** synthetic data, Blender rendering, ComfyUI dataset generation에는 강하지만 일반 PyTorch 실험에는 과하다.

**진단 → 가설 → 최소 실험:** synthetic-data 생성의 실패는 script 자체보다 잘못된 foreground instance·stale scene state·검증 없는 write에서 자주 생긴다 → discovery→describe→call→read-back contract가 silent failure를 줄일 수 있다 → 빈 Blender scene 또는 available DCC에서 object 1개 생성·속성 변경·undo를 실행한다. **GO:** target instance 1개만 선택, write/read-back 일치 2/2, undo 후 baseline 복원, 다른 file write 0. **KILL:** tool response가 이전 call과 섞임, 잘못된 window 조작, remote listener 자동 노출.
