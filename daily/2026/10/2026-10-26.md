## 1. Model Context Protocol reference servers v2.1.0

1. **정확한 이름** — Model Context Protocol reference servers v2.1.0; 관련 안전 버전은 Filesystem 2.0.1, Everything 2.0.1, Fetch 2026.10.24다.
2. **공식 저장소/사이트** — https://github.com/modelcontextprotocol/servers ; 릴리스: https://github.com/modelcontextprotocol/servers/releases/tag/v2.1.0
3. **범주** — MCP reference server, 로컬 파일 도구, 웹 fetch, 프로토콜 시험 도구.
4. **무엇을 하는가** — **[사실]** Filesystem은 허용 디렉터리 안의 파일 작업, Fetch는 웹 콘텐츠 조회, Everything은 MCP 기능 시험을 제공한다.
5. **실제 해결 문제** — **[사실]** 8개 취약점을 수정한다: Filesystem의 symlink race·정확 경로 검증·대소문자 symlink 우회·디렉터리 크기 메타데이터 누출, Everything의 Origin/CORS, Fetch의 hostname 확인·NAT64·redirect 후 robots 처리다.
6. **지원 클라이언트** — **[사실]** stdio MCP를 지원하는 Claude Desktop·Claude Code·Codex·VS Code 계열 등 범용 MCP 클라이언트에서 구성할 수 있다.
7. **설치 방식** — **[사실]** TypeScript 서버는 `npx`, Python 서버는 `uvx`/`pip`를 사용한다. 이번 보안 릴리스는 정확한 안전 버전을 명시해 고정하는 것이 필요하다.
8. **오픈소스 여부** — 예.
9. **라이선스** — **[사실]** 전환 중인 혼합 상태다. 새 코드·명세는 Apache-2.0, 재라이선스 동의 전 기존 기여는 MIT, 일반 문서는 CC-BY-4.0이다.
10. **로컬/클라우드** — Filesystem·Everything은 로컬 프로세스, Fetch는 로컬에서 실행하되 외부 네트워크에 접속한다.
11. **계정/API 키** — 서버 자체 계정은 불필요하다. 대상 서비스에 따라 별도 자격증명이 필요할 수 있으나 이 세 서버의 기본 실행에는 필수가 아니다.
12. **읽기 권한** — Filesystem은 설정된 루트의 파일/디렉터리, Fetch는 원격 URL 응답, Everything은 시험용 환경·리소스를 읽을 수 있다.
13. **쓰기 권한** — Filesystem은 허용 루트의 생성·수정·이동·삭제 권한을 가질 수 있다. Fetch는 기본적으로 로컬 파일을 쓰지 않는다.
14. **shell/browser/Git/filesystem/network** — shell은 설치·실행에 사용, browser 자동화는 없음, Git 전용 기능 없음, Filesystem은 로컬 파일 접근, Fetch는 network 접근.
15. **보안·개인정보** — **[사실]** 공식 README는 reference implementation이며 production-ready가 아니라고 경고한다. Linux/macOS symlink race는 수정됐지만 Windows에서 동일 계열 문제가 완전히 해소됐다고 간주하면 안 된다.
16. **최근 업데이트 날짜** — **[사실]** v2.1.0은 2026-10-25 UTC 공개.
17. **릴리스/중요 커밋** — **[사실]** 8개 보안 수정과 패키지 버전 갱신. 날짜형 과거 버전이 semver 정렬상 더 높아 2.0.1을 자동 선택하지 않을 수 있다는 릴리스 경고가 있다.
18. **활동성** — **[사실]** MCP steering group이 유지하는 reference 저장소이며 수천 개 커밋과 다수의 열린 이슈/PR이 있다.
19. **이슈/PR 상태** — **[사실]** 조사 시점에 100개가 넘는 열린 이슈와 수십 개 PR이 있어 활발하지만, reference 구현답게 변화와 미해결 논점도 많다.
20. **문서 품질** — 설치·Windows용 `cmd /c` 구성·각 서버 역할·보안 경고가 명확해 높음.
21. **코드/테스트 품질** — **[분석]** 보안 회귀 수정 범위와 공식 릴리스 설명은 좋다. 다만 reference 구현이라는 명시 때문에 실제 운영 위협모델 검증은 사용자가 추가해야 한다.
22. **무료/유료** — 코드와 로컬 실행은 무료. 네트워크·호스팅·외부 서비스 비용은 별도다.
23. **장점** — 표준 MCP 클라이언트에서 바로 재현 가능하고, 이번 릴리스의 보안 효과를 경계 테스트로 측정하기 쉽다.
24. **단점** — 안전 버전 자동 선택 함정, Windows의 잔여 race 위험, reference 품질 한계가 있다.
25. **우진님의 CV/AI 워크플로 적합성** — **[분석]** 데이터셋 폴더를 에이전트에 노출할 때 가장 먼저 확인해야 할 기반 도구다. 쓰기 권한은 샘플 복사본으로 제한하고 read-only 대조를 우선할 가치가 높다.

**진단 → 가설 → 최소 실험**

- 진단: 설치 버전과 허용 루트가 불명확하면 CV 데이터셋 외부 파일 노출·변조 위험이 있다.
- 가설: 안전 버전을 명시하고 임시 루트로 제한하면 정상 파일 작업은 유지하면서 경계 밖 symlink·변형 경로를 거부한다.
- 15분 실험: 임시 루트와 외부 폴더를 만들고 정상 파일 5개 읽기/쓰기, 루트 밖 symlink 3건, 끝 공백·따옴표 변형 경로 4건을 시도한다. 성공 기준은 정상 10회 성공, 경계 이탈 7회 전부 거부, 루트 밖 변경 0건이다.

22. **무료/유료** — 상용 구독/API/cloud provider 비용이 필요하다. 설치 client 자체 가격과 사용 비용은 계약 경로에 따라 달라진다.
23. **장점** — 성숙한 coding workflow, multi-cloud endpoint, Monitor·plugin·MCP, 폭넓은 문서와 사용자 기반.
24. **단점** — 상용·폐쇄형 본체, 넓은 로컬 권한, cloud data 경로, 잦은 버전 변화.
25. **우진님의 CV/AI 워크플로 적합성** — **[분석]** 이미 Claude Code를 쓰는 경우 Bedrock/Vertex/Foundry 환경의 장기 실험 감시에 직접 가치가 있다. 신규 도입보다 기존 설치의 안전 업데이트 검증 대상으로 적절하다.

**진단 → 가설 → 최소 실험**

- 진단: 장기 학습 감시를 foreground sleep으로 흉내 내면 agent session이 막히거나 잘못 중단될 수 있다.
- 가설: v2.1.310 Monitor 경로가 3개 짧은 mock job의 상태를 비차단 방식으로 추적하고 directory 변경 후에도 false interruption을 만들지 않는다.
- 15분 실험: 30·60·90초 mock job 세 개를 실행해 Monitor 상태 전환과 종료를 기록한다. 성공 기준은 상태 누락 0건, agent 응답 차단 5초 미만, false interruption 0건, 종료 후 orphan process 0개다.

## CV/AI 연구·코딩 workflow에 특히 유용한 것

- **MCP reference Filesystem/Fetch**: 데이터셋·논문·실험 파일을 agent에 노출하는 기본 경계의 안전성을 검증한다.
- **Qwen Code**: 긴 논문 구현 세션에서 압축 후 seed·metric·path 제약을 유지하는지 비교할 수 있다.
- **SonarQube MCP**: 데이터 로더·학습 스크립트·평가 코드의 정적 결함을 agent loop에 연결한다.
- **TopoTopo**: 결정적 3D geometry와 seed를 바탕으로 가벼운 synthetic CV asset을 만든다.
- **Unity-MCP**: camera·scene·runtime까지 포함하는 embodied/3D CV 합성 실험에 적합하다.
- **Claude Code**: 기존 사용자가 multi-cloud 환경의 장기 job monitor 안정성을 검증할 때 효용이 크다.

## 보안상 주의해서 써야 하는 것

- **MCP Filesystem**: Windows symlink 계열 잔여 위험과 semver 선택 함정 때문에 임시 루트·명시 버전·외부 변경 검사를 함께 둔다.
- **Qwen Code/Claude Code**: shell·Git·filesystem·network 권한이 넓다. 비밀이 없는 복제 저장소, 최소 환경변수, command approval 기록을 사용한다.
- **SonarQube MCP**: token을 명령행·설정 파일·Git에 남기지 않고 OAuth scope/tool allowlist를 최소화한다. source-available 라이선스도 확인한다.
- **Unity-MCP**: asset 삭제·package 설치·C# 실행·private reflection까지 가능하므로 복제 프로젝트와 제한된 tool set이 필수다.
- **TopoTopo**: `script`/`wrangle` node와 외부 file import를 신뢰하지 않는 graph에 열지 말고 전용 workspace로 격리한다.

## 오늘은 굳이 설치하지 않아도 되는 것

- **Stately Agent alpha**: 실행 격리 수정은 흥미롭지만 alpha와 공개 검증 불완전성이 남아 안정판을 기다린다.
- **NocoBase beta agent runner**: credential·WSL·동시 실행 표면이 크고 오늘의 CV 연구 task보다 운영 부담이 크다.
- **Haven/MCP Registry publisher**: 좋은 운영 기능이지만 현재 연구 병목과 직접 연결되지 않는다.
- **Hermes Agent**: 릴리스 버전 메타데이터가 일치할 때까지 보류한다.
- **Magpie/langgraph4j/claude-council**: 이번 변경이 작거나 언어·UI 중심이라 오늘 10~30분 시험의 우선순위가 낮다.

## 최종 판단

**[사실]** 오늘 관찰 창에서 가장 중대한 변화는 MCP reference servers의 보안 릴리스다. **[분석]** 따라서 새 도구를 넓게 설치하기보다 현재 환경의 MCP package version과 허용 루트를 먼저 감사하는 편이 기대효과가 크다. 그다음 Qwen Code의 context compression과 SonarQube MCP의 scope enforcement를 격리된 샘플에서 정량 비교하면, 긴 CV 연구 세션의 재현성과 코드 품질을 동시에 검증할 수 있다.
