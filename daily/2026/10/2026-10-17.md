## 2. Chrome DevTools MCP

1. **정확한 이름:** Chrome DevTools for agents (`chrome-devtools-mcp`).
2. **공식 저장소/사이트:** [GitHub](https://github.com/ChromeDevTools/chrome-devtools-mcp), [Chrome 문서](https://developer.chrome.com/docs/devtools/agents).
3. **종류:** Chrome 제어·디버깅·성능 분석용 MCP 서버와 CLI.
4. **무엇을 하는가:** **[확인 사실]** 라이브 Chrome의 DOM, console, network, screenshot, performance trace, Lighthouse 및 heap 관련 도구를 agent에 제공한다.
5. **해결 문제:** 사람이 DevTools 탭을 오가며 재현하던 웹 데모 오류·성능 저하·메모리 문제를 agent가 측정 가능한 로그로 수집하게 한다.
6. **지원 클라이언트:** Claude, Cursor, Copilot, Antigravity 및 MCP client; CLI 단독 사용도 지원한다.
7. **설치:** Node.js LTS, Chrome stable 이상, npm이 필요하며 MCP command는 `npx -y chrome-devtools-mcp@latest`다. 기본 작업만 할 때 `--slim --headless`를 쓸 수 있다.
8. **오픈소스 여부:** 예.
9. **라이선스:** Apache-2.0.
10. **로컬/클라우드:** MCP 서버와 Chrome은 로컬에서 실행한다. CrUX field data 조회와 통계·업데이트 확인은 네트워크를 사용할 수 있다.
11. **계정/API key:** 기본 로컬 사용에 별도 API key가 명시되지 않았다.
12. **읽기 권한:** 브라우저 페이지 내용, DOM, console, network, trace, heap snapshot 등 현재 Chrome session의 데이터를 읽을 수 있다.
13. **쓰기 권한:** 클릭·입력·navigation·script evaluation 등으로 페이지 상태를 변경할 수 있다.
14. **shell/browser/Git/filesystem/network 권한:** `npx` shell 실행, Chrome 제어, 웹 네트워크 접근이 필요하다. v1.11.0은 로컬 script file 평가 기능도 포함하므로 파일 접근 범위를 명시적으로 제한해야 한다. Git 권한은 필요하지 않다.
15. **보안·개인정보:** **[확인 사실]** 브라우저에 보이는 민감정보가 MCP client에 노출될 수 있다. usage statistics는 기본 활성화이며 `--no-usage-statistics`로 끌 수 있다. CrUX URL 전송은 `--no-performance-crux`로 막을 수 있다. 별도 profile과 `--isolated` 사용이 안전하다.
16. **최신 업데이트 날짜:** 2026-10-16.
17. **최근 release/commit:** [v1.11.0](https://github.com/ChromeDevTools/chrome-devtools-mcp/releases/tag/chrome-devtools-mcp-v1.11.0)은 heap context 분석, ffmpeg 없는 screencast, Lighthouse 결과 개선, config watcher 등을 추가했다. 10월 16일 commit `2777fa05b296`은 third-party developer tool 탐색 순서를 수정했다.
18. **활동성:** 조사 시점 약 53.7k stars, 하루 안에 여러 commit과 신규 PR이 생성됐다.
19. **Issue/PR 상태:** 열린 항목 163개. 10월 16일 logpoint, iframe `wait_for`, performance test 관련 PR이 열려 있어 개발이 활발하다.
20. **문서 품질:** 높음. 요구사항, 기본/슬림 설정, 보안 고지, telemetry opt-out, advanced guide, tool reference가 연결되어 있다.
21. **코드/테스트 품질:** TypeScript 기반이며 release note가 PR·commit과 연결되고 test migration PR도 관찰된다. **[판단]** 변화 속도가 빠르므로 `@latest` 대신 검증된 버전 pin이 재현성에 유리하다.
22. **무료/유료:** 무료 오픈소스. 사용하는 웹 서비스나 LLM 비용은 별도다.
23. **장점:** 공식 Chrome 프로젝트, 관찰과 조작을 한 서버에서 제공, 성능·메모리 분석 범위가 깊다.
24. **단점:** 브라우저 session 권한이 넓고 telemetry가 기본 활성화다. 로그인된 개인 profile에 연결하면 노출 면적이 커진다.

## 3. Potpie

1. **정확한 이름:** Potpie.
2. **공식 저장소/사이트:** [GitHub](https://github.com/potpie-ai/potpie), [공식 문서](https://docs.potpie.ai).
3. **종류:** AI-native SDLC용 local-first CLI 및 context graph.
4. **무엇을 하는가:** **[확인 사실]** 코드·구조·결정·source history·팀 지식·workflow를 graph로 색인해 agent의 질의, 계획, 디버깅, 코드 작성을 지원한다.
5. **해결 문제:** 저장소가 늘어날수록 agent가 매번 구조와 과거 결정을 다시 읽는 비용을 줄인다.
6. **지원 클라이언트:** Claude Code, OpenAI Codex, Cursor, OpenCode. GitHub, Linear, Jira, Confluence integration을 문서화했다.
7. **설치:** `uv tool install potpie` 권장, 또는 `python3 -m pip install --user potpie`; 이후 `potpie setup`.
8. **오픈소스 여부:** 예.
9. **라이선스:** Apache-2.0.
10. **로컬/클라우드:** 기본 setup은 local config, storage, daemon, pot, agent skill을 만든다. account-backed/managed 기능과 외부 integration은 cloud/API 연결을 쓸 수 있다.
11. **계정/API key:** 로컬 기본 기능과 별개로 `potpie login`, `potpie github login`, `potpie linear login` 등이 있다. 연결하는 서비스의 인증이 필요하다.
12. **읽기 권한:** 등록한 repository의 코드·history와 선택한 GitHub/issue/document integration 데이터를 읽는다.

9. **라이선스:** MIT.
10. **로컬/클라우드:** 로컬 plugin과 local snapshot storage.

12. **읽기 권한:** DSH session event, write-class tool이 다룬 파일, 추적 파일의 현재 상태를 읽는다.
13. **쓰기 권한:** session log에 rewind marker를 append하고, 사용자가 “대화와 코드” 복원을 선택하면 workspace 파일을 덮어쓴다. snapshot은 `<dsh home>/rewind-snapshots/`에 저장된다.
14. **shell/browser/Git/filesystem/network 권한:** DSH plugin 실행과 filesystem read/write가 필요하다. Git 의존성·network 요청·credential 접근은 없다고 README가 명시한다.
15. **보안·개인정보:** 삭제 대신 marker/hidden semantics를 사용하고 snapshot을 복원 근거로 삼는다. 다만 file restore 자체가 파괴적일 수 있어 변경 목록 확인과 별도 Git commit이 안전망이다.
16. **최신 업데이트 날짜:** 2026-10-16.
17. **최근 release/commit:** v0.16.0-alpha.2는 snapshot 크기·anchor group·cleanup 주기를 config로 옮기고, 복원 중 race·staged copy leak·released fs reference 문제를 고쳤다.
18. **활동성:** 조사 시점 138 stars, 같은 날 release와 DSH alpha 호환 commit이 이어졌다.
19. **Issue/PR 상태:** 열린 항목 1개이며, DSH 0.2.0-rc2에서 활성화되지 않는 bug 보고다.
20. **문서 품질:** 높음. 설치 패키지명 혼동 경고, 추적 경계, storage, 네트워크·credential 비접근, 알려진 한계를 명시한다.
21. **코드/테스트 품질:** TypeScript 기반, CI badge와 security 문서가 있다. **[판단]** alpha host 호환 범위가 좁아 production 안정성 판단은 이르다.
22. **무료/유료:** 무료 오픈소스.

24. **단점:** DSH 전용, alpha release, 하위 agent 편집 등 추적 경계 밖 변경은 완전 복원이 보장되지 않는다.

## 오늘은 굳이 설치하지 않아도 되는 것

- **dsh-rewind:** DSH를 현재 주력으로 쓰지 않는다면 alpha plugin 도입 이득이 작다.
- **CC Switch:** 두 개 이상의 agent/provider 설정을 자주 바꾸지 않는다면 기존 config 관리가 더 단순하다.
- **Activepieces:** 연구 레이더에 실제 외부 서비스 orchestration 요구가 생길 때 도입해도 늦지 않다.
- **context-mode:** 이번 시간 창의 commit이 기능 개선보다 통계 갱신 중심이었다.
- **LifeClaw:** 전화 발신이라는 권한·개인정보·비용 위험이 현재 연구 workflow 가치보다 크다.
- **Leapmux/Tachyon:** 각각 prerelease 성숙도와 Java/Kotlin 중심 적합성을 더 관찰한다.

## 진단 → 가설 → 다음 최소 실험

- **진단:** 현재 레이더는 정보를 Markdown으로 잘 축적하지만, 복잡한 관계를 도식화하고 여러 연구 저장소의 코드 근거를 재사용하는 단계는 수작업 비중이 높다.
- **가설 A:** draw.io MCP를 쓰면 연구 구조도 초안 시간을 줄이면서 편집 가능성을 유지할 수 있다.
- **가설 B:** Potpie와 Serena를 분리 평가하면 “장기 context”와 “정밀 code navigation” 중 실제 병목이 무엇인지 알 수 있다.
- **가설 C:** Chrome DevTools MCP를 격리 profile에서 사용하면 웹 데모 검증을 자동화하면서 개인정보 노출을 통제할 수 있다.
- **다음 최소 실험:** 오늘은 Top 3를 서로 독립된 공개 자료와 임시 환경에서 실행하고, 정확도·시간·노출 건수만 기록한다. 기준을 통과한 도구만 실제 연구 저장소에 연결한다.

## 전망

- **[전망]** draw.io MCP와 Serena는 산출물이 파일·diff로 남아 연구 재현성과 리뷰 가능성을 높일 가능성이 크다.
- **[전망]** Potpie는 보고서와 코드의 장기 연결에 가장 큰 잠재력이 있지만, graph freshness와 근거 추적 정확도가 가치의 핵심 병목이 될 것이다.
- **[전망]** CC Switch 같은 통합 관리 도구는 편의성과 credential 집중 위험이 함께 커지므로, 설정 수가 충분히 많아진 뒤 도입하는 편이 합리적이다.
