8. 오픈소스 여부: 예, 공개 GitHub 저장소.
9. 라이선스: 저장소 및 데이터별 라이선스를 별도로 확인해야 한다.
10. 로컬/클라우드: 코드·데이터는 로컬 실행 가능하되 선택 모델 provider는 원격 API일 수 있다.
11. 계정/API 키: 외부 model provider를 쓰면 해당 API 키가 필요할 수 있다.
12. 읽기 권한: 데이터셋·설정·모델 응답·평가 artifact.
13. 쓰기 권한: 결과 로그·캐시·생성 산출물.
14. 셸/브라우저/Git/파일시스템/네트워크: Python·파일시스템·Git 설치가 필요할 수 있고 외부 모델/데이터 접근 시 네트워크를 사용한다.
15. 보안/프라이버시: API 키는 secret manager/환경변수에만 두고 로그에 프롬프트·이미지 경로가 남는지 점검한다.
16. 최근 상태(사실): 공식 저장소의 최근 변경을 이번 72시간 탐색에서 확인했다.
17. 평가 규모(사실): 저장소는 6개 데이터셋에 걸친 1,200개 이미지 case를 설명한다.
18. 재현성 장치(사실): Hugging Face revision과 data lock으로 입력 버전을 고정하는 방식을 설명한다.
19. 제약: 모델 endpoint·가격·rate limit이 결과 비용과 재현성에 영향을 준다.
20. Issue/PR: 개별 open/closed 비율은 수치화하지 않았다.
21. 문서: task 정의·실행·데이터 고정 방식이 문서화돼 있으나 model adapter는 사전 검토가 필요하다.
22. 코드/테스트: 공개 코드·고정된 입력 지점이 있어 최소 재현 실험에 적합하다.
23. 가격: 코드 가격은 확인하지 못했으며 원격 모델 호출비는 별도다.
24. 장점: 일반 채팅 평가가 아닌 이미지 작업 단위에서 도구 사용 실패를 관찰한다.
25. 약점 및 CV/AI 적합성(해석): provider 차이와 비용 때문에 순위 하나로 일반화하면 안 된다. VLM agent·이미지 분석 smoke test에는 매우 적합하다.

**최소 실험 (30분):** data lock을 유지한 채 20개 case만 추출한다. 동일 모델·온도·도구 제한으로 두 번 실행해 task success, tool-call 수, 실패 유형, 호출 비용을 기록한다. 2회 결과가 다른 case는 성능 비교에서 분리한다.

## Top 3

1. **NVIDIA ModelOpt:** BEVFormer/VLM의 실제 배포 성능-정확도 측정에 가장 직접적이다.
2. **System One Bench:** 이미지 업무 단위에서 VLM agent의 도구 사용 실패를 드러낸다.
3. **Paseo:** 장시간 연구 자동화의 세션 단절 비용을 줄일 수 있다. 단 beta·파일 복사 정책 검토가 전제다.

## CV 연구에 특히 유용한 조합

- ModelOpt로 baseline/INT8/FP8을 비교하고 지연시간·VRAM·정확도를 같은 split에 고정한다.
- System One Bench의 data lock으로 provider·prompt·tool policy를 한 변수씩만 바꾼다.
- Paseo는 체크포인트·.env·개인 데이터가 있는 worktree에서 ignored-file 복사를 비활성화한 뒤 쓴다.

## 보안 경고

- Orchestrkit은 hook/tool dispatcher가 파일·셸 권한으로 이어질 수 있다. default allow가 아닌 명시 allowlist에서 시작한다.
- Paseo의 ignored-file 복사 기능은 비밀값·대형 artifact 복제 위험이 있다.
- Deploy Log MCP는 외부 네트워크 연결이다. 내부 저장소명·API 키·미공개 연구 키워드를 query에 넣지 않는다.
- ModelOpt/System One Bench는 모델·데이터 다운로드 및 원격 provider 사용 시 별도의 라이선스·비용·전송 경로가 생긴다.

## 지금 설치하지 않을 것

- 이번 창에서 공식 근거가 충분하지 않았던 Claude Code, Copilot CLI, MiMo Code, PR-Agent는 업데이트만을 이유로 설치하지 않는다.
- Codex alpha는 현 환경과 중복되고 prerelease이므로 별도 격리 환경 없이 확장하지 않는다.
- Orchestrkit은 read-only 차단 시험을 통과하기 전 실제 연구 저장소에 설치하지 않는다.

## 다음 30분 실행 순서

1. ModelOpt에서 고정 ONNX sample의 baseline/INT8 지연시간·VRAM·정확도를 측정한다.
2. System One Bench 20-case 반복 실행으로 변동성과 tool-call 실패를 기록한다.
3. Paseo는 비밀값 없는 임시 worktree에서 daemon 복구와 ignored-file 동작만 시험한다.
4. Orchestrkit과 Deploy Log MCP는 네트워크·셸·파일 쓰기 로그가 보이는 격리 환경에서 read-only 검증만 한다.
