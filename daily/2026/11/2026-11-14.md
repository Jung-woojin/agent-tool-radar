## 1. LangGraph 1.2.21

**선정 판단:** 연구 branch의 결과가 섞이면 모델 성능보다 먼저 workflow state routing을 의심할 가치가 있다. 이번 변경은 이 가설을 작은 fixture로 확인하기 좋다.

1. **정확한 이름:** LangGraph Python 1.2.21.
2. **공식:** [repository·README](https://github.com/langchain-ai/langgraph), [release](https://github.com/langchain-ai/langgraph/releases/tag/1.2.21).
3. **종류:** stateful agent orchestration framework.
4. **기능:** graph 실행, checkpoint, interrupt 및 subgraph 상태 관리.
5. **해결 문제:** 장시간 연구 작업의 재개와 분기별 상태 추적.
6. **지원 client:** Python application. JS는 별도 LangGraph.js 프로젝트이며 이번 Python 수정의 적용을 보장하지 않는다. ChatGPT/Codex의 직접 plugin은 아니다.
7. **설치:** 격리 환경에서 `pip install langgraph==1.2.21`. 이번 실행에서는 설치하지 않았다.
8. **오픈소스:** 예.
9. **라이선스:** MIT; repository metadata와 README에서 확인.
10. **로컬/클라우드:** 로컬 library 실행 가능. LangSmith deployment·tracing은 별도 선택.
11. **account/API key:** graph 자체의 로컬 fixture는 불필요. 실제 model·hosted tracing 사용 시 해당 인증 필요.
12. **read 권한:** 연결한 node/tool 및 checkpoint store 범위.
13. **write 권한:** checkpoint 저장과 사용자 정의 node의 side effect. 파일·Git write가 자동 제한되는 sandbox는 아니다.
14. **shell/browser/Git/filesystem/network:** 연결한 Python tool 권한을 따름. 이들을 기본적으로 모두 제공한다는 뜻은 아니다.
15. **security/privacy:** 잘못된 namespace로 다른 실험 상태를 읽거나 갱신할 위험을 점검해야 한다. hosted trace에 prompt·연구 데이터가 포함될 가능성도 설정별 확인.
16. **최근 update:** release published_at 2026-11-12 18:06:43 UTC = 11/13 03:06:43 KST.
17. **중요 변화:** `get_subgraphs`의 prefix 매칭을 segment 단위로 수정. undeclared namespace 조회 수정 및 filelock/langgraph-api 보안 갱신 포함. [PR #9615](https://github.com/langchain-ai/langgraph/pull/9615)는 11/06 merge되어 release 공개일과 구현일이 다르다.
18. **개발 활동성:** 최근 release와 sync/async 회귀 수정 확인. 활동량 자체를 품질 점수로 사용하지 않았다.
19. **issue/PR 상태:** #9615 closed·merged. JS 후속 수정 필요성이 PR에 적혀 있으나 해당 후속 반영은 미확인.
20. **문서 품질:** 설치·durability·interrupt·memory guide가 분리되어 있다. namespace 동작 변경은 PR 예시가 구체적이다.
21. **코드/테스트:** `pregel/main.py` patch에서 whole-segment 조건 확인. sync/async 테스트 파일도 확인. `make format lint test` 통과는 저자 주장이며 직접 실행하지 않았다.
22. **무료/유료:** MIT library와 로컬 fixture는 무료. model·hosted service·인프라 비용은 별도; 현재 요금표는 조사하지 않음.
23. **장점:** 실험 branch routing 오류를 model failure와 분리하기 쉽다.
24. **단점:** checkpoint schema와 side effect idempotency를 사용자가 설계해야 한다.
25. **CV/AI 적합성:** 높음. 재현·ablation·평가 branch의 실행 상태를 추적할 때 유용하며 GPU 학습 자체를 빠르게 하는 도구는 아니다.

**진단→가설→최소 개입:** 비슷한 node 이름에서 상태 혼선 관찰 → namespace prefix가 원인이라는 가설 → 모델 없이 `research`, `research_review`, `research|review`만 구성 → 정확한 namespace 매칭 여부 검사. trial의 수치 기준은 마지막 표에 제시한다.

## 2. Mastra core 1.83.0

**선정 판단:** 연구 서비스를 MCP로 노출할 때 별도 server 구현을 줄일 수 있다. 다만 “read-only 목록”과 실제 실행 권한, stream 재연결과 작업 복구를 분리해 검증해야 한다.

1. **정확한 이름:** Mastra `@mastra/core@1.83.0`; 내장 endpoint는 관련 `@mastra/server` 변경과 함께 봐야 한다.
2. **공식:** [repository·README](https://github.com/mastra-ai/mastra), [release](https://github.com/mastra-ai/mastra/releases/tag/%40mastra/core%401.83.0).
3. **종류:** TypeScript agent/workflow framework 및 MCP service.
4. **기능:** agents, workflows, memory, evals, MCP 노출과 실행 stream 관찰.
5. **해결 문제:** 연구 도구를 client마다 중복 통합하고 연결 끊김을 작업 실패로 오인하는 문제.
6. **지원 client:** Node/TypeScript application, MCP client. Claude Code 연결 예시는 공식 PR에 있음. 다른 client별 호환 시험은 미실행.
7. **설치:** 공식 scaffold는 `npm create mastra@latest`. 재현 trial은 core/server/MCP peer의 호환 버전을 고정한 별도 프로젝트가 필요하다.
8. **오픈소스:** core 대부분 공개; enterprise 부분은 source-available.
9. **라이선스:** core는 Apache-2.0, `ee/` 디렉터리는 Mastra Enterprise License. 전체를 단일 OSS license로 취급하지 않는다.
10. **로컬/클라우드:** 로컬 Node server 또는 자체 배포. cloud 사용은 선택.
11. **account/API key:** model provider 인증 및 server bearer credential. mock model trial은 provider key 없이 설계 가능.
12. **read 권한:** `mcp:read`로 연결·목록 확인; 기존 HTTP auth/RBAC/FGA를 적용한다는 설계.
13. **write 권한:** `mcp:execute`와 개별 route 권한. `readOnly`, toolset·include/exclude로 노출 축소 가능.
14. **shell/browser/Git/filesystem/network:** 등록 tool과 server process 권한에 의존. scaffold는 파일·의존성·경우에 따라 Git 초기화를 수행하므로 연구 repo 안에서 즉시 실행하지 않는다.
15. **security/privacy:** MCP endpoint가 노출면을 늘린다. bearer-only 인증, token audience, ownership, transcript/replay cache 저장 범위를 확인해야 한다.
16. **최근 update:** API published_at 2026-11-13 14:32:29 UTC = 11/13 23:32:29 KST. 웹 release 제목은 November 12여서 제목과 publish 시각을 구분했다.
17. **중요 변화:** resumable Agent streams, `/api/mcp`, OAuth discovery·audience checks, bounded schedules. `durable`은 stream 기능을 뜻하도록 바뀌었고 checkpoint 기반 실행은 `createDurableAgent`로 이전해야 한다.
18. **개발 활동성:** release와 endpoint 구현 PR의 최근 merge 확인.
19. **issue/PR 상태:** [#29929](https://github.com/mastra-ai/mastra/pull/29929) closed·merged, 11/12 17:56:29 UTC. README상 PR 작성은 collaborator로 제한; 외부 기여 경로 제약이 있다.
20. **문서 품질:** server/MCP 문서와 설정 예시가 변경에 포함되어 있다. migration은 package별 release를 같이 읽어야 한다.
21. **코드/테스트:** route/catalogue/config와 adapter parity 테스트 파일 확인. owner/viewer/no-token 및 Cloudflare 시험은 PR의 test plan이며 직접 통과를 재확인하지 않았다.
22. **무료/유료:** core는 무료 사용 가능; enterprise production 기능은 해당 license 필요. model·hosting 비용 별도.
23. **장점:** 기존 연구 서비스를 MCP로 연결할 때 auth 경로를 재사용할 수 있다.
24. **단점:** Python 중심 CV 코드에는 TypeScript service 계층과 저장 backend 운영이 추가된다. MCP optional peer가 없으면 501 응답한다.
25. **CV/AI 적합성:** 중간~높음. literature/benchmark 조회 service에 적합하며 단일 학습 script에는 과할 수 있다.

**진단→가설→최소 개입:** 연결 끊김 뒤 중복 연구 작업 발생 → 실행이 아니라 stream만 끊겼다는 가설 → side effect counter 하나를 둔 mock agent를 reconnect → counter와 replay event ID를 함께 확인. 권한 시험은 별도의 read-only mock tool로 제한한다.
