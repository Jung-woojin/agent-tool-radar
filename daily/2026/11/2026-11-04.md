13. 쓰기 권한: policy·signed ledger·receipt 및 Burn policy 파일을 기록할 수 있다.
14. 셸 권한: Bash와 tool hook을 정책 대상으로 삼는다.
15. 브라우저 권한: Codex local hook이 hosted WebSearch를 가로채지 못한다고 명시한다.
16. Git 권한: Git 자체의 직접 권한은 공식 문서에서 확인되지 않음.
17. filesystem 권한: AGENTGUARD_HOME 또는 ~/.agentguard와 plugin data 경로를 사용한다.
18. network 권한: provisioning은 npm 접근이 가능하며, key가 있으면 session start에 license refresh를 시도한다.
19. 보안·프라이버시: hooks가 모든 경로를 가로채는 것이 아니며 이미 승인된 shell의 write_stdin과 일부 specialized tool path는 우회될 수 있다.
20. 최근 상태(사실): 공식 Codex 문서는 현 hook path·compatibility·coverage 제한을 상세히 공개한다.
21. 핵심 정책(사실): Codex에서는 두 PreToolUse gate와 하나의 PostToolUse recorder가 .*를 대상으로 하며, Burn default limit은 15 subagents/15분, 40/120분으로 문서화돼 있다.
22. 실패 모드(사실): internal error 시 hook은 fail-open이며, policy가 필요한 경계는 tool/service boundary에서 별도 fail-closed로 보강하라고 문서가 권고한다.
23. 개발 활동/이슈: public source와 compatibility check 명령을 제공하나 issue 통계는 이번 원문에서 확인하지 못했다.
24. 문서·가격: free/paid tier와 Team의 seat 가격을 명시한다. Windows 실행은 검증되지 않았다고 문서가 밝힌다.
25. CV/AI 연구 적합성(해석): subagent 수와 장시간 experiment automation 비용을 가시화하는 데 유용하다. 다만 fail-open 성질상 dataset·production credential의 최종 권한 경계로 단독 사용하면 안 된다.

**최소 실험(20분):** 비밀값 없는 sandbox에서 read-only tool 10회, write 시도 2회, subagent 한도 도달 시도 1회를 수행한다. 성공 기준은 policy decision 13개가 모두 receipt에 남고, 거절 write 2건이 실제 변경 0건이며, 허용·거절이 host UI와 일치하는 것이다.

## 오늘 바로 설치/시험할 Top 3

1. **Agent Guard** — 연구 저장소의 API key·.env·Git commit 경로를 방어하는 즉시 가치가 있다. 15분 가짜 secret staging test부터 시작한다.
2. **Claude Agent ACP** — background task와 permission refusal을 client 단위로 추적해야 하는 경우에만 20분 sandbox session test를 한다.
3. **AgentGuard** — 여러 subagent가 비용·권한을 넓히는 작업에서 측정 가치가 있다. 단 실제 차단 경계가 아니라 관찰·보조 정책으로 시험한다.

## CV/AI 연구·코딩 workflow에 특히 유용한 것

- API key·dataset token을 쓰는 PyTorch/VLM 저장소: Agent Guard의 staged-change·Git 경계가 가장 직접적이다.
- 여러 재현·ablation을 agent worktree로 분리: Compozy의 session/PR monitor가 대기·상태 수집을 줄일 수 있다.
- 장시간 데이터 처리와 평가 agent: Claude Agent ACP의 background task·working directory 신호를 관찰하되, 각 agent의 data mount를 분리한다.
- 이미지 workflow prototype: AgentOS는 flow revision 충돌과 비용 게이트의 유무를 먼저 시험한 뒤 채택한다.
- 실험 자동화 비용 관리: AgentGuard는 subagent 수, tool 승인, receipt를 측정용으로 쓰고 최종 접근제어는 OS·repository·secret manager에 둔다.

## 오늘은 굳이 설치하지 않아도 되는 것

- **ModelOpt, Paseo, Orchestrkit, Deploy Log MCP, System One Bench:** 전일 보고서의 근거로 이미 평가했으며 오늘 새 변화가 확인되지 않았다.
- **ai-stp, GraphFlow:** 발견 신호는 있었지만 이번 창에서 공식 release·권한 문서를 충분히 교차검증하지 못했다.
- **Compozy:** PR/worktree orchestration이 당장 필요하지 않다면 도입 비용이 크다. repository·forge 권한 모델을 먼저 읽어야 한다.
- **AgentOS:** 이미지 flow가 실제 반복 병목이 아닐 경우, 새 runtime을 추가하는 비용이 이득보다 클 수 있다.
