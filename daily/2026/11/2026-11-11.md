## 1. GitHub Copilot CLI 1.0.109

1. **이름:** GitHub Copilot CLI 1.0.109.
2. **공식:** [GitHub release](https://github.com/github/copilot-cli/releases), [repository](https://github.com/github/copilot-cli).
3. **유형:** terminal coding agent.
4. **기능:** CLI session, shell/file workflow, MCP server 연결, subagent 및 sandbox policy를 제공한다.
5. **해결 문제:** agent의 repository 작업과 도구 연결을 terminal에서 운영한다.
6. **지원 client:** Copilot CLI가 중심이며 VS Code/Cursor/Windsurf terminal setup 관련 변경은 release에 명시된다. 다른 host의 native plugin 여부는 확인되지 않았다.
7. **설치:** 공식 release asset 또는 공식 install guide를 써야 한다. 이 실행에서는 설치하지 않았다.
8. **오픈소스 여부:** 공식 public repository가 존재하나, 전체 제품 구성의 라이선스 범위는 release만으로 판단하지 않았다.
9. **라이선스:** 이번 조사에서 license text를 재확인하지 못했다.
10. **실행 위치:** local CLI; GitHub-hosted 서비스와 model/provider 설정을 함께 쓸 수 있다.
11. **account/API key:** Copilot entitlement가 필요할 수 있으며 provider override의 정확한 조건은 환경별이다.
12. **read 권한:** workspace·GitHub code search·연결 MCP resource 읽기는 설정과 승인에 의존한다.
13. **write 권한:** file operations, shell, Git operation은 승인/policy 범위에 따라 발생할 수 있다.
14. **shell/browser/Git/filesystem/network:** shell/filesystem/Git/network/MCP를 다룰 수 있다. browser full-control 기본 권한은 공식 release에서 확인되지 않았다.
15. **보안/개인정보:** sandbox host allow/deny가 CIDR을 지원하게 됐지만, 허용한 network 범위·MCP endpoint·Git credential scope는 별도 검토해야 한다.
16. **최근 update:** 2026-11-10 release `1.0.109-1`; 안정 `1.0.109`도 release 목록에 표시된다.
17. **최근 변화:** CIDR sandbox allow/deny, sandbox path의 environment-variable 처리, interactive cache-aware wait; 직전 prerelease는 base64 text MIME MCP blob이 empty result가 되던 문제도 수정했다.
18. **개발 활동성:** release cadence와 공개 issue/PR 목록이 확인된다.
19. **issue/PR 상태:** 공개 issue는 많으며, 이 report에서는 특정 blocker triage를 하지 않았다.
20. **문서 품질:** release note가 command·setting·affected behavior를 구체적으로 적어 양호하다.
21. **코드/테스트:** Windows/macOS/Linux installer asset과 checksum은 보이나, 본 실행에서 test suite를 독립 실행하지 않았다.
22. **무료/유료:** Copilot plan/organization policy와 provider route에 따라 다르며 가격은 이번 실행에서 확인하지 않았다.
23. **장점:** MCP의 JSON/text blob을 쓰는 research connector에서 “빈 결과”를 data absence로 오판할 위험을 줄인다.
24. **단점:** CIDR allowlist를 넓게 잡거나 Git credential이 결합되면 local CLI라도 network blast radius가 커진다.
25. **CV/AI 연구 workflow 적합성:** 높음 — read-only paper/repo triage, bounded experiment-script 변경, MCP research connector inspection에 적합하다.

**진단→가설→최소 trial:** MCP blob decoding이 실제 research artifact 손실을 줄이는지 확인한다. disposable repo에서 `text/plain`과 `application/json` base64 blob을 반환하는 mock MCP tool을 10회 호출하고, 성공 decode 수·empty-result 수·network host 수·file write 수를 기록한다. decode 10/10, 예상 밖 host 0, write 0일 때만 research connector에 GO다.

## 2. Microsoft Conductor 0.1.45

1. **이름:** Microsoft Conductor 0.1.45.
2. **공식:** [GitHub release](https://github.com/microsoft/conductor/releases), [repository](https://github.com/microsoft/conductor).
3. **유형:** multi-agent workflow/framework.
4. **기능:** provider-backed agent와 workflow를 구성하고 실행하는 framework다.
5. **해결 문제:** agent/workflow의 model provider·default·실행 경로를 일관되게 관리한다.
6. **지원 client:** framework/API 중심이다. Codex/Claude Code/Cursor native plugin 여부는 release에서 확인되지 않았다.
7. **설치:** official repository/packaging guide를 따라야 하며 이번 실행에서는 설치하지 않았다.
8. **오픈소스 여부:** Microsoft의 public repository가 존재한다.
9. **라이선스:** 이번 실행에서 repository license file을 재확인하지 못했다.
10. **실행 위치:** local 또는 배포한 workflow runtime 구성이 가능하나, exact hosting model은 구성에 의존한다.
11. **account/API key:** 선택한 Anthropic/OpenAI/provider credential이 필요할 수 있다.
12. **read 권한:** framework 자체보다 연결 tool과 provider configuration에 의존한다.
13. **write 권한:** workflow에 tool/connector를 넣을 경우 발생할 수 있으며 default write policy는 확인되지 않았다.
14. **shell/browser/Git/filesystem/network:** native permission surface는 release에 완전 열거되지 않았다. provider network access는 필수이며 tool integration 범위를 별도 audit해야 한다.
15. **보안/개인정보:** agent가 model ID를 생략할 때 framework default에 의존하면, retire된 model·변경된 provider path로 request가 갈 수 있다.
16. **최근 update:** 2026-11-10 `0.1.45`.
17. **최근 변화:** model을 지정하지 않은 Anthropic agent가 retired `claude-3-5-sonnet-latest`를 쓰며 실패하던 경로를 `claude-sonnet-4-6`으로, OpenAI default를 `gpt-5-mini`에서 `gpt-5.6-terra`로 갱신했다.
18. **개발 활동성:** Microsoft-maintained repository에 versioned release와 signed commit이 있다.
19. **issue/PR 상태:** release는 #621·#628을 연결한다. 전체 open issue 건강도는 이 실행에서 판정하지 않았다.
20. **문서 품질:** default model transition의 원인·retirement 시점을 적어 migration 판단에 충분하다.
21. **코드/테스트:** default-fallback regression fix는 공식 release로 확인했지만, 여러 provider의 end-to-end test는 독립 검증하지 않았다.
22. **무료/유료:** framework와 provider inference/host 비용을 분리해야 하며, price는 provider 계약에 따른다.
23. **장점:** research agent가 model ID 누락으로 조용히 멈추는 operational failure를 잡기 쉽다.
24. **단점:** framework default를 신뢰하면 model·cost·behavior 변화가 experiment variance로 섞일 수 있다.
25. **CV/AI 연구 workflow 적합성:** 중간~높음 — paper triage·benchmark report agent에 explicit model manifest를 강제할 때 유용하다.

**진단→가설→최소 trial:** model default 수정이 reproducibility를 회복하는지 확인한다. toy workflow 3개를 model ID 명시/미명시 조건으로 각각 실행해 start success, resolved model ID, provider error, response schema pass rate를 기록한다. 미명시 조건에서도 resolved model이 manifest로 남고 실패 0일 때만 GO하며, 논문/benchmark 작업은 미명시 mode를 production default로 쓰지 않는다.

12. **read 권한:** project files·policy·checkpoint artifact를 읽는 scope가 필요할 수 있다.
13. **write 권한:** saved approval가 cover하는 action·file·project·environment에 따라 file/Git write가 가능해질 수 있다.
14. **shell/browser/Git/filesystem/network:** CLI/workflow가 local filesystem과 agent tool을 조정한다. 정확한 browser/network defaults는 공식 release에서 확인되지 않았다.
15. **보안/개인정보:** “한 번 승인한 scope”가 broad path 또는 mutable environment까지 묶이면, 다음 task에 privilege가 과도하게 이어질 수 있다.
16. **최근 update:** 2026-11-10 `v2026.11.4`.
17. **최근 변화:** bounded scope의 saved authorization grant, Windows fix, Grok Build preview, Codex/Copilot/Hermes discovery 개선; release assets에 Sigstore signature가 제공된다.
18. **개발 활동성:** 11월 10일 release와 11월 7일·5일의 연속 release가 확인된다.
19. **issue/PR 상태:** repository에는 공개 PR가 보이나, specific blocker는 이번 실행에서 확인하지 않았다.
20. **문서 품질:** 승인 scope와 checkpoint 목적을 release notes가 설명한다. full permission semantics는 install 전 docs 재검토가 필요하다.
21. **코드/테스트:** release asset signature는 확인되지만, 독립 security audit 또는 test suite 결과는 확인하지 않았다.
22. **무료/유료:** source/asset은 공개되어 있으나, model provider와 optional service 비용은 별도다.
23. **장점:** 반복되는 read-only report/triage task에서 handoff와 bounded approval 기록을 남길 수 있다.
24. **단점:** saved approval를 “agent가 안전하다”는 보증으로 해석하면 권한 확장이 발생한다.
25. **CV/AI 연구 workflow 적합성:** 중간 — experiment log summarization·read-only literature update에는 좋지만 training run·cloud credential scope에는 즉시 적용하지 않는 편이 안전하다.

**진단→가설→최소 trial:** scoped saved approval가 prompt 반복을 줄이되 write blast radius를 늘리지 않는지 본다. disposable repository에서 `reports/**` 읽기와 `notes/trial.md` 단일 write만 승인하고, 5회 task에 대해 approval prompt 수·허용 외 write 수·Git diff file 수를 기록한다. prompt 감소와 허용 외 write 0이 동시에 만족해야 GO다.
